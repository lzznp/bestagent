## 2. 实现内容（对照 HANDOFF §7 实施要点）

| 要点 | 实现 |
|---|---|
| 形态 | ✅ 本地面板，读 `business.db`（只读）+ 写自己的反馈账本，跑链路照旧用 run_pipeline，互不冲突 |
| ① 岗位列表 → 点进一岗 = 一条流程 | ✅ 侧栏岗位单选（当前 2 岗：GPGPU 架构师 277 人 / 中国移动 NLP 30 人）；主区顶部**状态条**展示 3 步骤时间线（①岗位分析 ②候选人评估 ③联系跟进·远期），并提示"现在卡在哪个步骤、等你什么动作" |
| ② 每步骤一张报告卡片（数据从库读） | ✅ **① 岗位分析卡片**：库内结论（总分/25、评级、接单判断）+ 岗位要素；若 outbox 有匹配的 `report_*.json` 则自动展开评分依据/风险清单/4 组搜索关键字（实验记录）。**② 候选人评估卡片**：库内真实统计（池子人数/平均分/最高分/结论分布）+ 推荐 Top10（姓名/总分/结论/亮点/顾虑/一句话）+ "查看全部 N 位候选人"（结论+分数筛选）+ 逐人评估明细与简历原文懒加载；单批池岗自动关联池评报告（评级/缺口/优势，当前 NLP 岗可展示） |
| ③ 卡片上按钮 确认/纠错（写批注）/放行 | ✅ 每张卡片动作行：**确认（采纳）/ 纠错…（写批注弹层）/ 放行**；动作按"岗位→步骤"追加进成长账 `data\feedback\<job_code>.json`（纠错带批注原文归档；侧栏有全岗台账汇总：采纳/纠错/放行计数 + 最近一笔） |
| ④ 顶部状态条 | ✅ 见上；步骤状态 = 账本中该步骤最近一笔（⏳等你处理 / 🟡已确认 / 🔧有纠错待消化 / ✅已放行） |
| 行为默认 v0.1 | ✅ 每步默认停住等老板（面板不自动推进 agent）；纠错"消化成方法论规则"的提炼动作 v1 不做自动化，只归档（授权矩阵 §7-2 停住等老板、§7-3 记采纳/纠错两笔账） |
| 不做项 | ✅ 无登录/多用户/美化；③ 联系跟进仅占位；与 3080 不冲突 |

**数据映射说明（诚实原则：库里有啥显示啥）**：卡片主体全部读 business.db；"池子评级/风险清单/关键字实验"等 agent 判断细节目前**未入库**（只在 outbox JSON）——v1 用文件自动关联兜底：岗前分析报告按 岗位名+公司 文本匹配；池评报告按"候选人 verdict 分布与库内完全一致"匹配（GPGPU 岗 277 人是 3 批合并，无单一文件对应，故只展示库内统计，不硬造池评）。

## 4. 与设计/任务包的偏差

1. **报告卡片"富化"走文件关联而非纯库读**——因 business.db 的 jobs 表当前只存 job_score 摘要字符串，完整岗前分析（评分明细/风险/关键字）与池评未入库（run_pipeline 直写库时只写了摘要）。v1 从 outbox JSON 自动关联补全展示；无文件时如实提示。**根治建议**（后续小改）：import 时把整份 analyze/pool 报告 JSON 直写 jobs 表新列或独立表，面板就 100% 只读库。
2. 验收单点流程（AppTest 自动化）**未含浏览器人工目验**——界面观感等老板试用反馈后迭代（符合"边用边改"）。

## 5. 遗留与下一步建议

1. **老板试用本面板**（北极星）：确认卡片信息密度/按钮语义/状态条文案是否顺手 → 反馈迭代。
2. **库内直写报告字段**：run_pipeline/import_to_db 增加 analyze_json/pool_quality_json（或独立 step_reports 表），面板去掉文件匹配逻辑（推荐小改，见偏差 1）。
3. 纠错账 → 方法论规则的"消化"半自动化（界面可加"已消化"标记 + 汇总导出，供转 prompts）。
4. 步骤③ 联系跟进、多页/美化：均按 v1 边界后置。
