### 2.3 三处"看起来成功、其实没做"的病（【已实测】→【已修】）

| 病 | 现场 | 修法 |
|---|---|---|
| **①拍板没落盘** | 老板说「**我们做这个岗位吧**」→ `detect_decision_intent` **一个词都没命中**（词表里是"做吧"，被"这个岗位"隔开）→ 落自由对话 | v1.8.5 **疑似拍板 → 面板本地反问**（0 花费、绝不替老板记）；老板回「是/对」= 对一个**已明确陈述的动作**点头才记，回「不是」= 当没说 |
| **②小猎假汇报** | 它回「收到——**「做吧」我记为接单（accept）**」，而 `state.decision` **仍是 pending**（**它没有这只手**） | v1.8.5 **面板事实核对**（`claims_recorded_decision`）：它声称"已记"而 state 没变 → **面板贴纠正**；+ `decision==pending` 时注入「拍板硬边界」（**其它时候 0 成本**） |
| **③采集条件校验算了没人看** | `execute_spec` 每个执行器都算了 `verify`（条件有没有真进"已选标签区"），**代码从不检查它** → `ok=True/verify=False` 静默通过 → **"条件没生效"被误读成"这个条件池子薄"** | `bridge-agent/agent/recipe_exec.py` **强制 verify**（硬失败 + 归因：档位不存在／文字不匹配／点错元素） |

> ①②是**同一个坑的第二次**（09-09「直接往下走吧，把这个岗位写入岗位」已经踩过一次，见 `job_profile.json` 的 events）。
> **根因**（09-13 重走复盘 §2.4 纪律②原话）：**"词表漏一个词，就等于代码替你拍了板"**。

### 2.4 ②"翻译考试"：给全合法值 → 它不迷糊了（【已实测】）

病根：`build_step2_plan_task` 只给 JD+①分析+方法论，**从来没把配方表的可选值给它** → 它只能**猜**（猜出过 `years=5-8年`，而猎聘只有 1-3/3-5/5-10/10年以上/自定义）。

两处修（都不花 token、不碰猎聘；**单源 = 配方表** `bridge-agent/agent/page_recipes.json`）：
1. 任务文本注入**可选条件清单**（`local_checks.recipe_options_brief()`，16 组 + 3 条已知坑 + "值只能从清单里选，不许自己编"）；
2. 计划落盘后**本地判分**（`local_checks.check_collect_spec()`）：组存不存在 / 值在不在合法档 / 关键字形态，
   不合法就**给最接近的合法档建议**（如 `5-8年` → 3-5年 / 5-10年；并提示「自定义」起止是**已知洞**）→ 面板贴 `🔍 …`。

**16:37 那一跑的成绩单**（【已实测】，老板亲手点）：

| 考点 | 表现 |
|---|---|
| AND 坑 | ✅ 4 条关键字全是 **2 个词**、不叠同义词，还解释了为什么分路 |
| **年限那个坑** | ✅ **没犯**，而且**主动不设 `years`**，理由"JD 要 3 年+、PM 说经验不限；设 3-5年 会误杀老手、设 5-10年 又漏 3-5 年 → 建议先问死 PM" |
| 值只从清单选 | ✅ `city_current=南京`、`education=本科` 均合法，本地判分通过 |
| 城市两维度 | ✅ 自己提出"首轮太薄就换成 `city_expected=南京` 扩池" |
| 合规/风控 | ✅ 性别、年龄、统招、薪资不设；"只翻列表不开详情页" |
| **它替我们发现的洞** | ✅ 它写"`education=本科` 若为**精确匹配**会漏硕/博，命中异常少就撤掉" → **学历"可多选"这条配方表没记**（老板口径：大专+本科+硕士+博士 = 大专及以上） |

1. **风格必须落在"数据"上，不能落在"代码"上**（`rules.md` / `job_profile.json` / 配方表 / 词表这些**喂食口**）；
