## 2. ④打招呼：现在怎么跑的【已实测】

**老板定的口径（照做）**：
1. **不携带岗位**打招呼（发岗有 30 个上限、上新岗要下旧岗 → 不走那条路）；用平台**默认短语**（"你好~我这里有个职位很适合你…"）；
2. **紧接着就发岗位介绍**——不等回复。理由（老板原话要点）：候选人端只看得到**最后一条的前 15 字**，两条一起发能让"岗位"留在会话里，**日后查看回复时才对得上"这位是哪个岗"**；
3. **岗位介绍由打招呼报告生成**（`intro_msg`，报告写死、脚本照抄、一个字不许改）；
4. **测试期不暴露 AI 身份**；
5. 每个候选人处理完**关掉详情页**；**采集时绝不点打招呼**。

**执行链（`greet_exec.py`，每一步都校验，对不上就停）**：
```
new_tab(报告里的 url)
→ 元素列表里找『立即沟通』（若是『继续沟通』→ 跳过，不重复打）
→ click_by_text '立即沟通'
→ **轮询快照等弹层**（判据：元素里出现『不选择职位开聊』；最多 16 秒）
→ 点弹层里那个 114px 宽的按钮（= 不选择职位开聊；**没有文字，靠几何**）
→ 确认页面变『继续沟通』
→ 面板若是收起的 → 点『继续沟通』展开
→ type 岗位介绍到 textarea（placeholder『请输入文字，按Enter键发送』）→ **回读 value 校验**
→ click_by_text '发送' → 校验（输入框清空 / 会话出现该段）
→ 关闭详情页 → 落台账（candidate_events 加『打招呼』+ detail_json 存档原文）
```

**安全绳**：默认 **dry-run**（不加 `--yes` 一个人都不发）；开跑前过 `greeting_ready()`（报告在不在/新不新/现在能不能打）；`--limit N` 限人数；打过的自动跳过。

**用法**：
```powershell
python greet_exec.py --job-code J-CHAT-20260909-094907              # 只列清单（不发送）
python greet_exec.py --job-code J-CHAT-20260909-094907 --yes --limit 3
```

## 3. 本场修的三个真 bug【已实测】【根因已查证】

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 打招呼"点不动"（脚本每次报"没等到弹层"） | **脚本用 `body_preview` 判断弹层**，而它是 `bodyText.slice(0, 3000)`（页面末尾的弹层永远进不来）→ **必然误判** | 改成**看元素列表**（快照里是全的）；`greet_exec.py` 五处判断全换 |
| 2 | 扩展的点击"太假" | `background.js` 只发 `mousedown/mouseup + el.click()`：无坐标、无 pointer 事件 | 改成**带坐标的完整事件序列 + `elementFromPoint` 命中测试**（实测 B站从"点不动"→能跳转） |
| 3 | **态势卡与报告互相打脸** | `status_run.py` 不给 `--plan` 时用**代码默认时间窗**（周一~周五 09:30），没读 plan | 改成**自动读本岗最新 `greeting_plan_*.json`**（"规则是数据"） |

**另按老板要求**：`body_preview` 默认 **3000 → 8000**（可被调用方用 `preview_chars` 覆盖）。

⚠️ **一条要记住的教训**：本场我一度断言"**平台风控在挡我们、要改半自动**"——**是错的**。
真实原因是**我们拿"摘要"当"事实"**。以后判断"页面上有没有某东西"，**一律看元素列表**。

## 4. ⑤查看回复：开工书【下一个对话就做这个】

### 4.1 目标（老板口径）
- **纯读、0 花费、0 风险**：读职聊页 → 知道**谁回了、回了什么** → 落台账 → 报告分区从"等回复"变"有回复"；
- 老板原话："**先让小猎会说你好，看看谁回复了，他自己先记住就行**"；
- 顺带把 **`[已读]/[未读]`** 读回来（"[已读]但没回 = 看过没兴趣/在犹豫" → 将来"换个说法再联系"的目标）；
- **主动投递（海投）**：老板说**放到这个环节再讨论**（【待拍板】——他倾向"质量一般、优先级低"）。

### 4.2 数据源（已实测，配方表里也有：`h.liepin.com/im/showmsgnewpage`）
```
https://h.liepin.com/im/showmsgnewpage   ← 职聊页
  左列：会话列表（姓名 + 职位 + 时间 + 最后一句预览 + [未读]/[已读] + 未读数徽标）
  顶部签：全部 / 新招呼 / 我发起的 / 我回复的 / 有简历 / 全部职位 / 未读
  右侧：会话详情（沟通职位 / 求职期望 / 消息流 / 输入框[发送]）
  ⚠️ 列表是**异步渲染**的：navigate 后第一次快照常常只有『未选中会话』→ **等 4~8 秒并重拍**
  ⚠️ 点会话行的 span **有时不触发切换**（SPA）→ 要么换定位方式，要么只读列表（列表已够用）
```
**回复判定（建议）**：
- `[未读]`→对方还没点开；`[已读]`→点开过；**会话里出现"对方发的话" = 真回复**；
- 但要**排除系统/我们侧文本**：`您可以修改打招呼语，去修改＞＞`（我们发的短语路上线的痕迹）、
  `我想要一份你的简历，你是否同意？`（索要简历）、`超级聊聊`等。

### 4.3 建议实现（照 ④ 的样子：脑=小猎/报告，手=脚本）
建 **`reply_run.py`**：
```
1) 读最新打招呼报告（拿"我们打过谁"：candidate_id + 姓名 + source_id）
2) 桥 new_tab 开职聊页 → 等列表渲染 → snapshot
3) 解析出会话行：{显示名, 职位, 时间, 预览, 已读/未读, 未读数}
4) **对上号**：候选人在职聊页显示**全名**（如"翁志远"），我们库里是**打码名**（"翁**"）→
   ⚠️ 建议用**简历编号/source_id** 对上号（会话详情里可能有；**需先探一次**），
   或按"打码名首字匹配 + 职位"兜底，匹配不上就**如实报"没对上号"**（不许瞎认）
5) 落台账：candidate_events event_type='回复'（白名单在 job_db.EVENT_TYPES：
   打招呼/回复/面试/offer/入职/不合适/备注）——**只增不改**
6) 重出打招呼报告（本地渲染 0 token）→ 打印"等回复 N / 有回复 M / 今天读到几条新回复"
```
- 面板按钮 `📨 查看回复` 已经接好了：它调 `reply_run.py --job-code <岗>`，所以**只要把这个脚本写出来，按钮立刻可用**；
- 纪律：**只读**（不发送、不改页面）；读到什么记什么，**没读到就说没读到**。
