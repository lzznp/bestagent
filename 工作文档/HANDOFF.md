2. **采集必须走配方表 execute_spec**（`collect_liepin.py` 已封装）——用 /api/agent/run 自然语言循环会"条件没设上、直接 extract 页面残留结果"（实测采到青岛无关 40 条）。
3. **bash 工具在 Windows 不可用**（连 echo hello 都 File not found）；**pwsh 组合**（minimal-pwsh-nonpty.cordis.yml）可用，但 **SDK runtime 需 danger-full-access** 否则 spawn EPERM。
4. **不要配 terminal-bash + shellDialect: pwsh（PTY 模式）**——系统无 pwsh.exe，node-pty 直接崩（reading 'destroy'）。
5. **大池子评估分批 ≤72 人/批**（32768 token 上限，120 人已极限）；用 m2_eval_run.py --start/--end + merge_report.py 合并。
6. **agent 写的 JSON 带 UTF-8 BOM**——读取一律 utf-8-sig。
7. **公司名做关键字有同名噪音**（"海光"→食品/光电/贸易）；技能关键字（GPGPU/ROCm/CUDA/编译器/Runtime）更准（P6 教训印证）。
8. **限速默认 20 搜索/200 提取/天**（quota.py），防账号风控；打招呼（50/天）永远留人工闸门。
9. **新版 SDK 勿用**（master 0.1.2-alpha.2 架构大改 + Windows wheel 未发布），继续旧版 API。
10. 参考代码 `D:\study\bestagent\参考代码\` 只读素材库（README.md 有索引），活体在 `D:\study\lietou*`。
11. **条件筛选配方组已验证可用**（education=博士/博士后、years=应届生、city_current=北京…）——新 JD 采集务必用，前置过滤比后置评估省 token 提准；⚠️ 院校 C9/QS50 猎聘筛不掉（school 只有 211/985/双一流/海外留学）；⚠️ 活跃度对应届岗别设（应届普遍不活跃会筛空）。
12. **run_pipeline --step 要重复 flag**（`--step eval --step import`，不能 `--step eval import`）；`--skip-collect` 复用采集时文件名必须匹配（collected_<jd 文件名>.json）。
13. **猎聘学历筛 = 离散档**（不限/本科/硕士/博士/博士后/大专/中专/中技/高中及以下），**没有"本科及以上"** 这类档——条件值写错 execute_spec 点不到即整轮失败（已在 m3_chat 出计划模板写明提示）。
14. **猎聘搜词框=「包含全部关键词」（空格=AND）**：词内叠同义词/多词极易 0 命中；同义叫法该用「任意」模式或拆单概念词分路（当前 agent 固定"全部"，模式切换未支持）。
15. **大池子别让面板 ③/💬 一次跑完**：agent 单次输出有上限（自由聊天 8192 / 评估 32768 token），85 人"一次写文件"必断或空回复——**评估分批 ≤72/批（m2_eval_run）、打招呼数据 ≤5 人/批（greet_run）**；面板③大池自动分批 = v1.6.8 待修。
16. **agent 分片产物的 candidate_id 会按批内 1..N 重编号**（被 prompt 示例诱导）——**合并必须按唯一键（link 的 res_id）回填真实编号**（greet_run.merge_greet 已内置），勿按位置硬拼。
17. **HTML 报告一律本地模板渲染**（report_html.py 系），**禁止让 agent 手写整份 HTML/长 md**（大输出+费 token+版式不可控）；LLM 只产结构化小 JSON——数据/展示分离（老板 2026-09-05 拍板，见 PROGRESS「下午续」节）。
18. **平台风控真相（老板实测确认）**：「昨日数据」只统计 查看简历数/沟通/联系方式/云电话，**搜索次数不计**；几万查看简历数才异常 → 别为搜索次数缩关键字/缩手，管好轮间节奏（8-20s）+ 详情页查看量（detail 100/天 保险丝）。
19. **agent 任务文本里别写死样例岗内容**（greet_run.build_task 曾把中兴微"数字后端-模块交付/科锐国际/学历本科/年限1-3"写死成纪律 → 换岗必口径泄漏）——岗位硬性口径一律从本岗 analyze 报告动态提取（`_requirements_from_analyze`：difficulty.value 冒号后 → jd_extracted.requirements）；prompt 的 JSON 结构示例也只用中性占位。
20. **reports 目录里同名伴生文件**（analyze_<ts>.json 与 analyze_<ts>_过程.html、pool_report 与 匹配报告 HTML、greet 与 greet_part 分片）——找"最新产物"要按**前缀+后缀**过滤（如 `latest_final()` 排除 *_part_*、只取 .json），裸 glob 前缀会误读 HTML/分片。
21. **agent 要读多文件再产 JSON 的任务（发岗/计划类）**：任务文本**必须显式禁 bash**（Windows 必挂，agent 会先试 3 次浪费轮次）+ **max_tokens ≥16384**（4096 会在读手册+JD 后推理耗尽、没到写文件步即截断——publish_run 首跑实测踩坑）——同 m3_chat persona 工具纪律，凡新 agent 任务都要带上。
22. **发岗文字 = 数据/展示分离又一个好样板（wails publish 模式）**：LLM 只产 9 字段 JSON（实际招聘方非代招/多城「/」并列/职责删网站产品名/优先条件单列），本地拼职位描述 + 薪资换算（万+薪→K·薪）+ HTML 渲染——agent 手写整篇 md 是反模式（大输出+费 token+版式不可控）；合规规则沉淀在 `data/prompts/publish_manual.txt`（手册），临时发现的公司要求追加进「五、公司特别提醒」（优先级最高）。
23. **猎聘诚猎通（h.liepin.com）表单实测（2026-09-06）**：创建职位页 = React SPA，无障碍名大量缺失——不少控件"按文本点"点不到（如「+新增代招企业」入口在 a11y 树不可见）→ 定位优先"index+rect 坐标带 + 每次动作后重快照"，别指望 click_by_text 全覆盖；**代招企业 = 账号企业库**（企业管理页管理）：在库可搜可点选，选中后平台自动打码「对外展示:某XX公司」= 防候选人绕单机制（与发岗手册"内部信息不进文案"同逻辑）；**不在库企业输入/粘贴无效 → 只能走「+新增代招企业」弹窗**（代招企业名称 + 对外显示名称两输入框，名称自动补全）→ **新客户入库 = 老板人工一次性**（入库后该公司自动可选）；h.liepin.com **开 F12 会白屏**（反调试/反爬），刷新即恢复——自动化走桥 snapshot 不受影响，老板日常别开 F12。
