## 2. 本场主要结论

### 2.1 目标：**资产已经替你投过票了**

反方只有两条，而且都是"仪式"不是"资产"：① persona 第一句把他说成"助手" ② 每次都由老板验收。

**证据（全在资产里）**：闸门设在"打招呼／发岗"（都是**对外说话**）｜桥的定义就是"**小猎跑腿**"｜系统名"猎头 AI **操盘手**"｜有 `business.db` 和岗位目录（**工具不需要账本，操盘手才需要**）。

→ **判断：终局是"替身"**（放手），不是"工具"。
→ **而现状是：资产往替身长，人设和验收仪式还停在工具——这个不一致，就是"感觉啥也不懂"的来源之一。**

**待确认而已**：报告模板的收件人是谁（给老板看 vs 给客户看）。这一个问题能定案。

### 2.2 纪律：分四类，不再混着叫"已定结论"

| 类 | 有哪些 | 判据 |
|---|---|---|
| **真纪律**（与工具无关） | LLM 出判断／代码出结构；不可逆留闸门；约束落机制不落提示词；工具面越小越便宜 | DSH 明天消失也成立 |
| **处境纪律**（被逼的，条件可松） | 不赌会话记忆（一半是 `session already exists` 逼的） | 换 runtime 就要重估 |
| **假纪律**（其实是"没试过"） | **"不装插件"**——实测 `profiles\sdk\package.json` 的 `dependencies` 是 `{}`，`cordis.patch.yml` 是空 `[]` | 事实是**未验**，写下来却像**方针** |
| **过期的自我认知** | "学历只有离散档、没有'本科及以上'"——**实测页面上就是多选**（见 §6.5） | 硬编码在提示词里的知识，且**是错的** |

**🔴 今天明确了一条纪律的违反现场**：§4.2 说 `web_search`/`web_fetch` 挂着，"防线只有 persona 里一句话"——**自己定的纪律自己没守**。

### 2.3 设计：四形式表要补一档

§2 那张表要把 **①′ 配置层（patch）** 补进去：

| | 模型怎么知道 | 手从哪来 | 权限 | 用什么写 | 加/改成本 | 作废吗 |
|---|---|---|---|---|---|---|
| **①′ 配置层 patch** | 我们写进 patch | **不给手** | — | yml | **重启** | 不 |
| ① 本地代码 | 我们写进提示词 | 借 `pwsh` | 🔴软 | 任何 | 0 | 不 |
| ② 技能 | 自己翻手册 | 借 `pwsh` | 🔴软 | 一个 md | 极低（watcher） | 不 |
| ③ MCP | 工具清单 | 独立进程 | ✅硬 | 任何语言 | 中（多进程） | 不 |
| ④ 插件 | 工具清单 | 运行时内部 | ✅硬 | TS/Node | 高（装+重启） | **会** |

**一句话判据**：能改配置就别写代码，能放文件就别装包，能开进程就别进运行时。

**⚠️ 补一条 §2 漏掉的 MCP 代价（推导，未实测）**：MCP 的工具**常驻工具清单 → 每轮收租**。
（佐证：`docs\user\guide\mcp-memory.zh.md:82` 提到等 `mcp__…` 工具出现 → MCP 工具确实进模型工具面。）

### 2.4 新纪律（**双向**，老板拍）

> **① 不让 LLM 干代码的活**：能本地代码处理的就不让它操作——它只吐文字（字段级小 JSON），本地渲染、本地转义。省 token，而且可控。
> **② 不让代码干 LLM 的活**：拿不准的、需要判断的，别用词表 if/else 替它决定。**词表漏一个词，就等于代码替你拍了板。**

**判据**：**错了会不会系统性传染**——会传染 → 代码；只错一处、人能一眼看出 → LLM。

**参考实现**：`greet_run.py` 产小 JSON → `report_html.py` 本地渲染（0 token、`esc()` 全程转义）。
**出处**：`report_html.py:9` 那行注释 + 产物页脚"本地渲染（LLM 只产字段 JSON，本页可随时重生）"。

**住哪一层**：按 9-07 成长三层，这是「**工具纪律**」→ **基因层（内建不学）**，不进 `rules.md`。

**两处活的违反现场**：
- **LLM 干了代码的活**：`_过程.html` 由 LLM 手写整份 HTML
- **代码干了 LLM 的活**：`m3_chat.py` 里 **13 个词表**（`TEACH_WORDS`／`PROFILE_WORDS`／`ACCEPT_WORDS`／`COLLECT_WORDS`／`EVAL_WORDS`…）；代价实证 = "**直接往下走吧**"漏拍板词表 → **自解读 accept**

### 2.5 "快"是假象——采集太浅

**老板原话**："我感觉有点快了"。机制上是这个（**已逐条验代码**）：

```
一个关键字只看一页（~30 人）→ 不调活跃度 → 不抽详情 → 换个词再来一遍 → 三页人直接进池评和打招呼报告
```

**铁证**：`collect_liepin.py:91-129` **没有任何翻页代码**，一次 `extract` 抓当前页；
§3.6 实测"3 个关键字 = 86 人" → 86÷3 ≈ **29**，正好一页。✅

**对照页面**：同一个条件页一次搜索报 **3000+** → **我们采到的是搜索结果的 ~1%。**

**⚠️ 由此得出一个偏乐观的机制性粉饰**：`pool_quality`（池子评级）评的是**这 30 个**，而不是 3000+；而**第一页是「智能排序」的头部**，质量天然偏好。
→ **池评会偏乐观。这是机制造成的，不是谁在骗人。** 与 §5.2 待拍板第 2 条（「匹配难度」失去实证来源）同病。

**而普通猎头做对了、我们没做的四件事**（老板口述）：
看**质量拐点**（约 10 页／300 人，越来越差就停）｜**换关键字再看、换活跃度再看**｜用**「隐藏已查看」**｜**边看边打**。

### 2.7 闸门全在门外面（本场最深的机制发现）

`framework_config.py:47`：

```python
PERMISSION_MODE = "danger-full-access"   # 无头运行：danger-full-access 时 approval 自动为 never
```

**串起来的因果（推断，但三处症状全对得上）**：

```
无头运行 → 必须 danger-full-access → approval 自动 never
        → 运行时里一道闸门都没有 → 只能"事前"拦：词表 + persona
```

| 症状 | 根因 |
|---|---|
| 要 13 个词表 | 没有事中闸门，只能事前拦 |
| `CAPABILITIES` 那条【歧义必问·基因纪律】 | 同上——拿不准时没有闸门挡，只能叮嘱它自己停 |
| `web_search` 防线"只有 persona 里一句话" | 同上 |

> **我们的闸门全在门外：面板的按钮、词表的分流、persona 里的一句话。运行时里面，一道都没有。**

**而词表真正干的不是"理解意图"，是"决定给不给它手"**——`detect_collect_intent` 的注释自己写着：
"只说'按补跑计划执行'未命中旧词表 → **走普通聊天、没挂 pwsh 工具 → 小猎无法真跑**"。

**DSH 有现成的**：`dsh-user-approval` / `dsh-permission-presets` / `dsh-tool-ask-user` —— **都在我们 profile 里装着。**

### 2.10 真实的形状：**长跑 + 会被打断 + 配额跨岗**

老板口述的真实工作形状（本场最重要的输入之一）：

- **打招呼 50 次/天** —— **唯一真正稀缺的东西**（搜索不计额度）
- **首次开聊占额度，继续聊随便**
- **没打满 50 → 再开一个岗**（配额**跨岗共享**）
- **第二天又是 50 个新配额**；回来第一件事是**看回复／主动投递**，不是继续采
- **打断是常态**：加急岗插队、网络断、电脑坏

**而"乱"的机制**（老板原话："脑子一乱，那不就不想干了吗"）：

> **不是"事情太多"，是"每件事都得靠脑子记"。**
> 脑子记不住 → 来回切 → 每切一次丢一次上下文 → 累 → 不想干。

**⚠️ 而且"打不满 50"这件事，本身就否掉了"靠加账号突破配额"的动机**（详见 §3.7）。

### 2.11 「记录」与「计划」必须分开——"可变的全自动"的答案

**现在 `state.json` 记的全是"我做过什么"**：

```
step1_analyzed=true ｜ decision=accept ｜ step2_collected=false ｜ step3_done=false ｜ last_action=发岗文字
```

**一条"我接下来要做什么"都没有。** 所以它天然不可变——只能**追加"又做了什么"**，改不了**"要做什么"**。

**要"可变"，得有两样东西：**

| | 性质 | 例子 |
|---|---|---|
| **记录（过去）** | **只追加，永不改** | 谁打的、什么时候、结果如何 |
| **计划（将来）** | **可改写** | 接下来干什么、按什么条件、哪一步人工 |

> **老板的插入语（"某岗条件改了"／"这个岗我回复"／"新开一岗"／"加急"）本质都是"改写计划"。**
> **"全自动"能不能"可变"，就看有没有这一份可改的计划。**

**⚠️ 而"条件改了"有个真金白银的坑**：重跑会**重新捞到已打过招呼的人** → **重复占用 50/天 配额**。
→ 平台的「**隐藏已沟通**」我们没用；`contact_status` / `candidate_events` **是空的**。**（今天第四次撞上同一个缺口。）**

### 3.7 为什么"多账号"暂不做

- 老板口述的障碍"**不同账号下候选人 id 不同**"——**这条不成立**：账号内编码只是**最强的键**，不是唯一的键。替代键 = **履历指纹**（公司＋职位＋起止月份＋学校＋专业＋毕业时间），**数据我们已经采到了**（`collected_*.json` 的 `text` 字段）；而且 §4.5 说上一代有「**三字段去重锚点**」，听起来正是干这个的
- **真正的理由是他自己的话**："第一天…这 50 个招呼**没打满**啊" → **打不满 = 配额有富余 = 配额不是瓶颈**
  - "打不满"若是**没时间** → 加账号不解决（还是一个人）
  - "打不满"若是**没人值得打** → 加账号更不解决（人还是那些）
- **还有一个坎比技术大**：50/天是平台的风控线，**多账号 = 绕它**。这不是"能不能"，是"该不该"

### 3.8 为什么"分身"暂不做

- **不是嫌麻烦，是单岗成本还没量过**：三个脑袋 × 未知单价 = 未知风险
- **而且边界很清楚**：**思考可并行，动手必须排队**（一个账号、一套限额、一套风控）
- **老板举的三件事里只有一件碰浏览器**：A 写推荐报告 ❌／**B 采集匹配 ✅**／C 岗位分析 ❌ → **不会互相抢**
- **`subagent` 一直挂着而我们从没用过**（`subagent` / `subagent_fork` / `list_agents` / `send_message` 都在 25 个工具里）
- **⚠️ 而且我们这套只有"进程内"的 provider**（profile 里是 `spawn-in-process` / `fork-in-process` / `in-process-driver`，**没有 `dsh-subagent-dsh-sdk`**）→ 现在真按下去起的是**进程内子 agent**，不是独立分身。**（挂载配置未验）**

### 3.9 为什么"可插拔小猎"是方向不是议题

- **"可插拔"四形式表已经回答了**：别人能加东西**零门槛的入口是 ② 技能**（一个 md、免重启）；要硬边界+不作废 → ③ MCP；要最紧集成 → ④ 插件（担升级）
- **但现状：四个插槽都有，我们一个都没插过**（技能目录不存在、没 MCP、没装过插件）——**跟"同事玩不出花样"是同一件事的另一面**
- **"提供一个刚出生的小孩"——这个小孩 DSH 已经提供了。** 我们的 value-add **不在底座，在"喂食口"**（岗位目录／配方表／`rules.md`／闸门位置／四形式的选择）
  → **"做一个可插拔的底座"是在跟 DSH 抢活，抢不过；"把喂食口做成可插拔的"才是我们的活**
