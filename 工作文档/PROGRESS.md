## M3 设计讨论记录（2026-09 设计对话 · 待跑单后定稿）

> 背景：按授权矩阵 §7 开的设计讨论对话。用户选择"先自己用起来、边用边改"，故只落暂定结论，未决点挂起待真实跑单后拍板回填。

**已对齐（暂定结论 + 理由）**

| 决策 | 结论 | 理由 |
|---|---|---|
| 汇报节奏模型 | **步骤制**：每完成一个业务步骤 → agent 交该步骤报告 → 老板看了沟通（确认/纠错/指示）→ 才进下一步；一个步骤内可多轮"报告→纠错→再跑"迭代 | 还原用户真人操作（模拟采集→心里有数→和 PM 沟通→再采→决定接单/放弃）；不是全链路跑完才汇报 |
| 步骤划分 | ①岗位分析（读JD→接单判断→拆搜索条件→探索采集→池子初判→做/放弃结论）②候选人评估（逐人评分）③联系跟进（远期，永远人工闸门）；探索采集是①的内嵌动作，非独立步骤 | 对照 recruitment-wails 环节还原（岗位分析双Tab + pool_samples + 云端匹配 + candidate_events） |
| 术语 | 对话/界面统一"步骤/报告/介入点"，不叫"环节"；与 run_pipeline --step（技术执行阶段）区分开 | 业务汇报断点 vs 代码阶段，防歧义 |
| 采集池设计 | 粗略候选先进临时池（pool_samples 式，用完即弃），值得挖的才沉淀正式库 | wails 已验证；run_pipeline 现直写正式库缺这一级（遗留待补） |
| 纠错资料（成长） | 双轨：①原始纠错按"岗位→步骤"归档（挂上下文）②消化后提炼成规则进方法论（data/prompts 等） | 全混一起丢上下文；只记不提炼 = 流水账非成长 |
| 界面形态 | 汇报面板（报告卡片+确认/纠错按钮+状态条）为主干，对话框为辅助（开放纠错/追问） | 决策 12 细化；结构化审阅用卡片表格，对话框不适合翻大池子 |
| 部署 | 源码方式自用（可改流程、agent 可改自己）；exe 打包下策；将来交付倾向整机预装（与源码方式兼容） | 边用边改 + agent 自我改进要求本地可写；软件层本就不防抄（决策 13） |
| 插件策略 | 不主动找：缺什么补什么、补了先验；工具类插件 SDK 通用，Web 界面类不通用 | 能力收敛、token 可控；新版 alpha 插件 API 与 rc.8 不兼容 |
| 学习机制 | 无强化学习/训练成分；成长 = 外部文档记忆（纠错→方法论），非模型权重 | 透明可控可审阅（决策 11） |

**挂起（§7 未决点 · 跑 N 单后拍板）**：
- ②闸门等待：临时默认 = 触发待拍板清单后 agent **停住等老板**；跑几单嫌拖再放开
- ③放手策略信号（采纳率 / 连续 N 单）｜ ④授权矩阵验收（分级/平台动作遗漏/限额数字）｜ ⑤信任破坏与恢复（降级/回滚）｜ ①-a 信任高后步骤断点是否保留（步骤制固定节奏 vs §4 递减节奏）
