### 2.3 自动翻页：解了【已实测】

- **根因（实测两次）**：① `click_by_text("下一页")` 找不到可点祖先——分页 `li` 没有 role/tabindex/onclick/class，文字在子节点里，我们的"可点判定"漏了它；② `click_by_text("4")` **点到了年龄"46岁"里的 span**（72 个候选匹配）——**页码是短数字，按文字定位必然撞车**。
- **解法**：新增 `click_paging`（**按分页结构点**）：优先 `.ant-pagination-next` 箭头（disabled 就换策略），否则点"当前页+1"的 `.ant-pagination-item`；点完等"页码真的变了"，返回 `{clicked, page_before, page_after, reason}`。
- **真页面实测**：`click_paging ok=True, clicked=next-arrow`。
- `reason`（`no-next` / `not-changed`）**直接当停止判据**，上层不用猜。

### 2.4 判据不再写死：按岗判据卡【已定 + 已实测】

**病根（第三次复发）**：第一版 `collect_rules.py` 把"电气设计·输送线"这一个岗的行业词/技能词/职能词**写成了模块常量**。换 094907（机械工程师）立刻歪：`叉车/AGV/穿梭车/提升机` 不在词表里，而且"纯机械 −25、无行业命中封顶 40"会把机械设计师全部沉底。

**改法**：**判据卡（JudgeProfile）**

```jsonc
// collect_plan_*.json 新增一节（小猎写）
"judge": {
  "hard": [],  "industry": [], "companies": [], "skills": [],
  "role": [],  "not_role": [], "prefer": "industry|skill", "notes": "..."
}
```

**三条不变量**（写进代码，模型只能给词、不能改权重）：
1. **权重写死**：行业 8/个(≤24)、技能 4/个(≤12)、本行职能 +10、学历/城市只做平手参考、**无行业命中封顶 40**
2. **本地不丢人**：`not_role` / 非本行 只降噪（降分、排后、不开详情），**照样入库**（丢人是③的事）
3. **缺卡不静默**：没给 `judge` → 用兜底（172253 电气那套）+ `used_default=True`，**轨迹/报告里标红**

**整卡制**（踩出来的）：给了卡就**用你给的**，缺哪个字段**留空**；只有整张卡都没有才整份兜底。
—— 第一版是"缺字段掉回电气兜底"，结果机械岗的卡里混进了"德马科技/兰剑"（电气行业公司名）→ 会把机械候选人误判成行业命中。

### 2.7 库层真 bug：`UNIQUE(content_hash)` 会**静默丢人**【已实测，已修】

写执行器单测时抓到：两个 `source_id` 不同、**简历原文恰好相同**的人，被第二条唯一约束当成同一人 → **丢掉一行**。

```
cards:   汪**(open) 宋**(open) 王**(skip)
db rows: rid_MECH_1(kept)  rid_IND_1(opened)   ← 宋** 不见了
```

**改法**：`content_hash` 降级为**复核信号**（只记 `dup_of`，不合并、不丢行）；`schema.sql` 升 **v2**，老库自动"重建表+拷数据"迁移（`job_db._migrate`）。**丢人比多留一行贵得多，而且真实数据里不报错。**
