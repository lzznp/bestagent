## 1. 产品愿景（2026-08-31 讨论定稿）

**一句话**：做一个"数字合伙人"——替你跑完整条猎头工作链路、主动汇报、从纠错中成长、最终让你完全放手的 AI 助理。

**用户原话的具象化**：
- 随便丢一个 JD（甚至它自己找岗）→ 自主跑链路（岗前分析 → 转关键字 → 猎聘采集 → 评估候选人池）→ **主动汇报"老板，我弄的咋样？"**
- 你从"不太信任"→ 检查 → 慢慢放手 → 完全信任
- 它从你的纠错里学习（记忆/技能）；你从它的建议里修正流程——**双向成长**

**三个关键词**：
1. **自主**：链路它自己跑，不等你叫
2. **汇报**：干完主动交作业（"我弄的咋样"），汇报粒度 = 信任演进的机制（待设计）
3. **成长**：从反馈中学习，你也在修正中成长

## 3. 决策记录表（防意图衰减）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 新项目形态 | 用 DSH SDK 做新一代"数字合伙人"；browser-agent/领域方法作为组件继承 | 一年资产验证过的东西不重写；SDK 已验证可跑 |
| 2 | 模型分层 | 云端分层起步；本地 Qwen 后置 | 零部署成本、效果确定；本地服务器电源老化；平台规则逼质>量 |
| 3 | 技术底座 | **DSH Python SDK**（headless、无人值守、程序化授权、会话记忆） | Windows 全链路实测通过（见《SDK 技术评估》） |
| 4 | harness 升级 | 暂不升级（旧版 0.1.0-rc.8 稳定运行；新版 alpha 且 Windows wheel 未发布） | 当前环境稳定；升级收益为零风险全担 |
| 5 | 产品愿景 | 数字合伙人：自主跑链路 + 主动汇报 + 信任演进 + 双向成长 | 用户原话具象化（见 §1） |
| 6 | 平台约束 | 猎聘 50 打招呼/天 + 查看统计 → 自动化必须限量、限速、像真人 | 生存规则：平台不允许"勤奋"，只奖励"准" |
| 7 | 验证策略 | **验证周**：最小实验（SDK agent 跑 真实JD→岗前分析→转关键字→汇报） | 固件教训：做出来才显形；避免"高效地做错" |
| 8 | 协作规矩 | ①动手前先对齐"目的声明" ②小步验证+回顾 | AI 加速"做"不加速"想"；两条规矩防做偏 |
| 9 | 应用扩展 | 底座通用（猎头 → 炒股等）；但资产不通用（各领域自攒数据资产） | 底座一次投入反复用；猎头是第一个应用 |
| 10 | 信任演进 | "老板我弄的咋样"汇报机制 = 产品核心设计点（汇报粒度待细化） | 从监督到放手的机制化，不是玄学 |
| 11 | 记忆实现 | 三层：SDK JSONL（会话）+ SQLite（业务，复用 wails 表设计）+ MD（偏好，MEMORY/SKILL） | 透明可控可审阅；RAG 后置（资产化已验证是浪费） |
| 12 | 工作界面 | 分阶段：文件 Inbox（验证周）→ Streamlit 汇报面板（M2/M3）→ 语音机器人（远期） | 验证周零 UI 先验核心；界面=信任演进载体 |
| 13 | 变现路线 | 后置；倾向"硬件+软件"整机（小智机器人+预装助手），非纯软件/算力服务 | 防复刻（硬件抄不动）；用户不想大规模服务 |
| 14 | SKILL 范围 | 只提炼方法论（岗前分析/采集流程等），代码资产 90% 原样复用 | SKILL 是操作手册不是代码归宿；不做全量改造 |
| 15 | 实体形态 | 远期：Wails 重构小智后台 + 固件连本地 = 语音终端（大脑=Wails agent，固件=纯终端） | 统一产品、复活小智资产、差异化演示；验证周不做 |

## 4. 明确不做 / 另行规划

| 不做 | 理由 |
|---|---|
| 全量候选人资产化（向量化整个池子） | 用户亲手验证过：时间成本高 + 岗找人场景用不上 |
| 人找岗（简历→岗位方向） | 猎头主场景是岗找人；人找岗是独立系统 |
| 卖代码/卖工具本身 | AI 时代代码贬值；资产 = 业务 know-how + 验证过的配方/提示词 |
| 机器人项目（AI 剧场/面试/传声筒） | 暂停，先做猎头主线（2026-08-31 用户决策） |
| 炒股助手 | 后置：底座通用但资产不通用，猎头先磨底座 |
