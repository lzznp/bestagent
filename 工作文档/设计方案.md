## 1. 产品愿景（2026-08-31 讨论定稿）

**一句话**：做一个"数字合伙人"——替你跑完整条猎头工作链路、主动汇报、从纠错中成长、最终让你完全放手的 AI 助理。

**用户原话的具象化**：
- 随便丢一个 JD（甚至它自己找岗）→ 自主跑链路（岗前分析 → 转关键字 → 猎聘采集 → 评估候选人池）→ **主动汇报"老板，我弄的咋样？"**
- 你从"不太信任"→ 检查 → 慢慢放手 → 完全信任
- 它从你的纠错里学习（记忆/技能）；你从它的建议里修正流程——**双向成长**

**三个关键词**：
1. **自主**：链路它自己跑，不等你叫
2. **汇报**：干完主动交作业（"我弄的咋样"），汇报粒度 = 信任演进的机制（待设计）
3. **成长**：从反馈中学习，你也在修正中成长

## 4. 明确不做 / 另行规划

| 不做 | 理由 |

| 全量候选人资产化（向量化整个池子） | 用户亲手验证过：时间成本高 + 岗找人场景用不上 |

| 卖代码/卖工具本身 | AI 时代代码贬值；资产 = 业务 know-how + 验证过的配方/提示词 |

## 6. 架构定位补充（2026-09-05 深夜对话定稿，防概念回潮）

> 背景：老板在"LangChain 多 agent"旧心智里困惑 harness 时代的架构归类，讨论后定稿。本节约定架构词汇与演进节奏，**新对话读到本文档时不要再从零讨论"是不是多 agent / 要不要自主端"**。

### 6.1 我们的架构是什么（贴标签）

- **当前 = 单 agent 流水线（可编程 agent 管道），不是 multi-agent**：同一个 persona「小猎」+ 同一模型被脚本反复调用，每次 run 干一步、靠盘上文件（JSON）交接，**agent 之间不对话、不委托、无记忆**（会话 JSONL 已证不可靠）。
- 不算 LangChain 式多 agent（无多角色互聊派活），也不算 DSH 自主端多 agent（无 agent 调 subagent 委托树）。
- **三权分离是本架构的骨架，想清楚它就不需要纠结标签**：
  1. **定流程** = 脚本/代码（auto_job.py / publish_run.py / m3_chat 按钮：确定性、可断点续跑、可单步重跑、省 token、可审计）——把编排权从 agent 手里收回来（LangChain 让 agent 自己定下一步 = 费 token + 不可测 + 会撒谎，v1.6.1~1.6.3 三轮实测为证）
  2. **做判断** = 小猎（每次拉起的无状态执行单元：分析/拆计划/评分/话术，只产结构化小 JSON）
  3. **批准动作** = 老板（闸门：采集计划确认 / 详情查看量确认 / 打招呼永远人工）
- **为何与 DSH 设计取向一致**：DSH = agent 是可靠执行单元、智能花在判断不花在记流程；我们用其"人/脚本调度 + agent 判断 + 文件记忆"一面（确定性端），暂不用其 subagent/goal/workflow 一面（自主端）。

### 6.2 要不要推进到"自主端"（节奏决策）

- **两层自主要分开**：
  | 层 | 是什么 | 时机 |
  |---|---|---|
  | 执行自主 | 脚本把"停等确认"换成"自动继续+跑完汇报"（auto_job 加 `--auto` 类开关） | **信任够了就放开**——最轻的自主，即"全自动"愿景的执行面 |
  | 判断自主 | agent 自己看结果决定补不补采/下一步（DSH goal/subagent/workflow） | **远期且需特定前提**（见下） |
- **推进信号（现在都未到，勿提前做）**：
  1. 老板开始烦"每步都停" + 成长账显示该步采纳率高 → 逐步放开：先③评估后自动详情深采 top N（可逆低风险）→ 再打招呼清单自动备好只等审 → 最后才谈自动打招呼（单独过授权关）。
  2. 出现脚本搞不定的不确定性（如"池子差该放宽重采还是换词"想让机器自己试）→ 才上判断自主（goal 受控循环：给边界、里面自试）。
  3. 多岗并行忙不过来 → "每岗一个 auto_job 实例并行"，最多加总调度，用不上"一群 agent 开会"。
- **油门不在技术，在成长账攒出的信任**：自主 = 省掉人的中间确认，前提是信任数据够；信任不足放开自主 = 让不熟的手下自己签字。故日常先跑顺攒纠错（见 PROGRESS「成长机制第一笔」），执行自主先来、判断自主后置。

## 7. 框架审视 v1（2026-09-07 设计讨论定稿，重校准）

### 7.1 一句话产品画像（v2 校准版，取代 §1 原话具象的产品引擎表述）

> **对话协作的猎头合伙人**：判断在对话里来回，小猎给态度和理由；它记得你们一起攒的方案与规律，同类岗越来越懂；攒够了你能按方案放手（"按方案 B 执行，JD 在这，我去喝酒了"），它只在该叫你时叫你；它的主战场跟着你走——沟通跟进，而不只是上游跑岗。

老板朴素三句：① 有个懂行的搭档能跟我聊判断；② 它记得我们一块儿攒下的东西、越用越懂我；③ 攒够了它能按方案自己接活，我放手去搞沟通。

### 7.2 与最初愿景（§1）的关系（定性）

- **定性**：愿景的现实校准 + 交互形态换代；非推翻、非倒退。保留：小猎做判断 / 脚本定流程 / 产物=资产 / 不可逆留闸门 / 记忆在文档。改变：①"自主"= 按已积累方案执行、人放手（不再是"agent 自己跑链路"）②交互 = 对话驱动判断（不再是步骤制面板发令）③成长 = 探索→方案（不再只是纠错→规则）。
- **被推翻的唯一想象**："丢个 JD 它自己全自动跑完整条链"。§1 的愿景文字保留为历史，产品引擎以本节为准。

### 7.3 四件套（决策 20-23 摘要）

| 件 | 结论 |
|---|---|
| 交互 | 判断在**对话**里完成（态度+理由+反驳追问）；执行走脚本/auto_job；产物自动留档；按钮 = 执行显示层；闸门保留。chat.py = 新对话 P0 |
| 对象 | 岗位 = **长期底座**（JD+资料+状态+历史+跟进），多岗并行 + "待我处理"总览；会话临时、岗长久 |
| 成长 | 三层挂载：基因层（诚实/边界/工具纪律，内建不学，persona 注入）/ 步骤经验层（rules.md 按步骤，做到那步才读）/ **岗型方案层（新增：同类岗整包打法 = 方案 A/B）** |
| 放手 | 对话把关 → 已验证步骤放行（--auto）→ 成熟方案整体授权；油门 = **方案成熟度**（岗型跑过次数/纠错率/老板亲手确认） |

### 7.4 主战场与资产化（决策 24-25 摘要）

- 主战场 = **沟通跟进**：平台侧"第一公里"自动 + 沟通状态/记录自动归集（candidate_events），转微信后上下文不断；微信侧远期；微信/电话/谈薪资永远人工不变（衔接 §3 #18）。
- 资产化：跑单 = 攒资产（每次探索/跑单产出岗型方案/搜索配方/报告模板/规则，三层归位）——用法从"自嗨"变可迁移资产（#9 底座通用 / #13 变现后置的落地口径）。

### 7.5 明确不变（防回潮）

架构 = 单 agent 流水线/三权分离（§6 不推翻）；可逆全自主/不可逆留闸门；数据/展示分离；UI=壳产物=资产；记忆在文档不在会话；成长不含模型训练（= 外部文档记忆）。
