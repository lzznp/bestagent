## 4. 事实（下一场直接用，**别重查**）

**A. 对话路的路由（全部四个分类器，`m3_chat.py`）**

| 分类器 | 触发条件 | 备注 |
|---|---|---|
| `detect_decision_intent`（拍板） | **必须 `decision == "pending"`**（`:2393`） | 现在 `decision=null` ⇒ **对话里根本记不了拍板** |
| `detect_rejudge_intent`（重新判断→重跑①） | `decision ∈ (decline, clarify)`（`:2424`） | 同上，进不去 |
| `detect_collect_intent`（②采集） | 有「猎聘/采集/搜索…」等词 → `plan`；再加「按计划跑/直接跑…」→ `run`（`:1292-1297`、`:1490`） | **误判高发区** |
| `detect_greet_report_intent`（出打招呼报告） | 有「打招呼报告/该打谁/出一份报告…」且 `step2_collected=true`（`:2446`） | 现在条件已满足 ✅ |

- **①分析（岗位分析）在对话里没有路由** ⇒ 只能落进自由对话。
- **发岗、④打招呼、⑤查看回复在对话里都没有路由**（发岗是纯按钮＋本地脚本 `publish_run.publish_for_job`；④⑤是子进程 `greet_exec.py`/`reply_run.py`）。

**B. 为什么"原话传不到它手上"（三条根因，同一个病）**
- `build_step2_plan_task(job)`、`build_step1_task(job)` 等**只接收 `job`，不接收老板原话** ⇒ 路由一旦判成某动作，**老板说的话就丢了**，小猎连"你是不是想要别的"都没法反问（§24.3）。

**C. 采集链（本地代码，**0 次 LLM**）**
- `collect_exec.py`（动手）＋ `collect_rules.py`（判断，**本地规则**）＋ `collect_liepin.py` ＋ 桥／扩展；grep `llm|deepseek|api_key` **0 命中**。
- 循环 = `for kw in kws`（`collect_exec.py:722`）⇒ **"该换词"只结束这一条关键字，不会停整轮**；整轮结束只有三种：跑完／人工停止（桥 `stopped_at`）／进程被终止。
- **轨迹与过程页只在 `main()` 收尾写**（`collect_exec.py:886-902`）⇒ **一断就全丢**。
- 对照先例：`runs.jsonl` 台账是"**开始就落盘**"（`m3_chat.py:1785-1786`）。
- 判据：页间「连续 2 页行业命中=0」、「本页 open=0 且已翻 ≥2 页」；页内「连续 10 个不值得开」；`max_pages` 默认 **0 = 不限**（死命令）。

**D. 面板与权限**
- 一轮 run **同步阻塞**（`m3_chat.py:2465-2472`）⇒ 跑着的时候面板干不了别的。
- 每轮 run = **新 session**（`:1783`）⇒ 无跨轮记忆，靠状态卡续上下文。
- **只有①分析分了工具档**（`TOOL_PROFILE_BY_ACTION = {"analyze": "bare"}`）；**自由对话是满工具面**（≈25 个工具）。
- 面板跑 agent 的权限模式默认 **`danger-full-access`**、approval 自动 never（`framework_config.py:47`、`:188`）。
- ①分析的 `max_tokens = 16384`，其它 8192（`:2466-2467`）。

**E. 盘上口径**
- `state.json` 的 `step1_analyzed` 是 `load_state` **从产物反推**（`:693-694`），不是运行处理写的。
- `decision` 只在 `action_kind == "analyze"` 时被置为 `pending`（`:2572-2578`）。
