## 3. 讨论已沉淀的方向（未落决策表，本场可拍板）

1. **映射 = 岗位"身份桥"**（禾蛙身份 ↔ 猎聘身份），会在 发岗回填 / 搜人认岗 / 沟通挂岗 / 投递归集 反复用到 → 按决策 26 应**长在岗位目录**（如 `data/chat/<job_code>/mapping.json`：hewa_job_no/hewa_url ↔ liepin_code/liepin_display_name(别称)/notes/linked_at），不是 db 表。
2. **别称问题**：猎聘用代招别称代替真实用人单位 → 映射存三样：禾蛙真实客户名（内部）/ 猎聘对外显示名别称（对外）/ liepin_code（系统）。别称错 = 沟通界面张冠李戴。
3. **动态发岗规则通道 A/B/C（三选一拍板）**：A=📋 时注入本会话老板最近原话当 notes（本次生效，零风险）；B=「记到发岗手册」进受控追加白名单（小猎只追加 §五、回读展示，需老板接受信任度）；C=两段式（rules.md⑤草稿池 + 实施侧提升手册）。上会话默认建议先 A。
4. **角色认知定调**（后续所有上游/沟通设计的前提）：交付物 = 靠谱候选人流 + 可联系性，不做 HR/PM 的精确筛选；沟通纪律/快捷回复已在 communicate_manual.txt。
5. **岗位资产库/PM 表**（相邻议题，非本场主线）：PM 表 = 活岗位源；工作区根目录有 `智库交付侧岗位需求及说明.xlsx`（7 岗样例，含我们正跑的机械工程师岗；未入库、未处理）。
