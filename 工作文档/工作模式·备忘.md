## 0. 一句话

**四个角色**：老板（操盘手，拍板）· 参谋长（DSH 对话里的 AI：观察/讨论/写文档/改代码）· 小猎（`m3_chat` 里的 agent：干活）· 桥（浏览器手脚）。

**日常形态**：老板在 PyCharm 起 Streamlit 页面（`m3_chat.py`）跟小猎干活；同时开着 DSH GUI，跟参谋长（我）讨论与交接。

## 1. 全景图

```
                    ┌─────────────────────────────────────────────┐
   老板（操盘手）    │  PyCharm 终端                                │
   定目标 / 拍板     │  streamlit run m3_chat.py                    │
   深度沟通 / 把关   │        ↓                                     │

                    │        ↓ 每个动作自己起进程、跑完关掉         │
                    │  DSH Python SDK（deepseek_harness）          │
                    │        ↓                                     │
                    │  node 运行时（bundled runtime + profile）     │
                    └──────────────┬──────────────────────────────┘
                                   │ 用的时候连
                    ┌──────────────▼──────────────┐
   参谋长（我）      │  桥 browser-agent :8080     │──▶ Chrome 扩展 ──▶ 猎聘（登录态）
   DSH GUI :3080    │  （浏览器手脚）              │
   观察/讨论/文档    └─────────────────────────────┘
   /改代码           ┌─────────────────────────────┐
                    │  DSH Web GUI :3080           │──▶ 参谋长（这个对话）
                    └─────────────────────────────┘
```

**要记住的类比**：老板 = 老板；参谋长 = 参谋部（不直接跑业务的脑）；小猎 = 业务员（跑岗干活）；桥 = 业务员的腿（去浏览器里跑腿）。**AI 不替代老板，接管机械活。**

### 1.1 三层运行边界（哪层能升、哪层不能碰）⭐

```
┌─ 主机环境（别人的）── DSH 本体 / Web GUI / 浏览器插件 / DSH 自带的 ~/.dsh
│                         → 随它升级，与项目无关
│  ┌─ 运行环境（必须有版本边界）── deepseek-harness-sdk + deepseek-harness-runtime-bin
│  │    + 项目自带的 dsh_home（bestagent\data\dsh_home）
│  │                         → pip 锁同一版本；项目不碰 ~/.dsh
│  │  ┌─ 我们的资产（自己的）── 文档 / rules.md / 配方表 / 岗位目录 / 产物 / business.db
│  │  │                      → 永远安全：不依赖任何 SDK 版本
```

| 层 | 谁的地盘 | 升级态度 | 依据 |
|---|---|---|---|
| 主机环境 | DSH 官方 | **随它升，无所谓** | 项目自带 `dsh_home`，与 GUI 完全隔离 |
| 运行环境 | 我们（pip 锁版本） | **只在需要时主动升**；一次升级成本 ≈ 11 个调用点 + persona + 工具面（半天到一天） | `DSH升级事故·衔接报告.md` §8.9 最终方案 |
| 我们的资产 | 我们 | 不涉及升级 | 决策 9（底座通用）/ 决策 25（跑单 = 攒资产） |

**两条铁律**：

1. **运行环境与主机环境之间不许共享目录** —— 项目既不读 `~/.dsh`，也不 `PYTHONPATH` 指向 DSH 源码。
   ⚠️ 2026-09-10 事故的根因，就是当年**共用同一个 checkout + 共享 home**：DSH 一升级，项目运行环境被就地替换 → 旧调用方式（`cordis` / `session_root` / `launch_args_override`）整体作废。
   （历史原因不是"选错"：当年官方 **Windows wheel 未发布**，只能挂源码。参见 HANDOFF 教训 #9。）
2. **pip 装了就必须删掉 `sys.path.insert(... DSH 源码 ...)`** —— 否则源码会**遮蔽** pip 的包，等于白装。

**为什么这次能半天到一天恢复**：最里圈（资产）从没绑在代码上。**那才是真正的护城河，不是 SDK。**

## 2. 四个角色的职责与边界

| 角色 | 在哪 | 干什么 | 不干什么 |
|---|---|---|---|
| **老板** | PyCharm + 浏览器 | 定目标、拍板、跟 PM/候选人深度沟通、把关风险 | 不做机械搬运（那正是要 AI 接管的） |
| **参谋长**（DSH 对话里的 AI） | DSH GUI（`dsh web`，:3080） | 读文档/读代码、侦察环境、设计方案、**写交接文档**、改代码与配置、陪老板讨论决策 | 不替老板拍板业务取舍；不可逆动作不自己动 |
| **小猎**（agent） | `m3_chat.py`（Streamlit） | 岗位流程执行：①岗前分析 ②探索采集 ③池子评估 ④发岗文字 ⑤打招呼清单；自由对话（只读+受控追加）；成长沉淀写 `rules.md` | 不做结构性修改（删/改记录、动代码）＝决策 27；不做自然语言驱动浏览器（教训 #2） |
| **桥** | `browser-agent`（:8080，Python + Chrome 扩展） | 浏览器手脚：快照/点击/输入/导航/标签页/结构化提取；**配方表 `execute_spec`** 确定性设置筛选条件 | 不自己决策（谁下指令谁负责）；不发不可逆动作（打招呼走人工） |

## 3. 谁拉起什么（易忘点 ⚠️ 含一条纠错）

| 组件 | **谁拉起** | 说明 |
|---|---|---|
| **小猎的 node 运行时** | ✅ **`m3_chat` 自己拉** | 每次执行 `run_assistant()` 起一个 node 子进程，**跑完关掉**（旧方式：`.dsh-staging` 闭包 + cordis；新版：bundled runtime + profile） |
| **浏览器桥 :8080** | ❌ **不是页面拉的** | 全项目**没有任何代码启动桥**。由**参谋长在 DSH 会话里当后台 job 拉起**，或老板双击 `start_bridge.bat`；`m3_chat`/采集脚本只在用时**连**它 |
| **DSH GUI :3080**（参谋长所在） | 老板 | 启动 `dsh web`（或快捷方式）；`~/.dsh` 是它的家目录 |
| **Streamlit 页面**（小猎所在） | 老板 | PyCharm 终端：`streamlit run m3_chat.py`（解释器 lzstudy，目录 `bestagent\`） |
| **Chrome 扩展**（桥的执行器） | 老板 | `chrome://extensions` 开发者模式加载；**猎聘登录态在浏览器里**，不在代码里 |
| **DeepSeek 模型** | 两边共用 key | key 在 `.env`（路径在 m3_chat 侧栏「运行设置」配） |

> ⚠️ **纠错（2026-09-10 老板口述版有误）**：老板记得"页面自己拉起运行时**和桥**" —— 运行时对 ✅，**桥不对** ❌。桥一直是参谋长/手动拉的。
> 💡 **改进候选**：让 `m3_chat` 一键把桥也拉起来（更符合直觉，少一个手工步骤）。

## 5. 记忆载体的三层（为什么"对话丢了不疼"）

| 层 | 载体 | 丢了会怎样 |
|---|---|---|
| **跨对话记忆** | `工作文档\`（HANDOFF / PROGRESS / 衔接报告 / 本备忘 / rules.md） | 这是**唯一**的跨对话记忆。丢了 = 真的丢了 → 所以每阶段收尾必须写 |
| **业务底座** | `data\chat\<job_code>\` + `business.db` | 岗位与产物。丢了要重跑（所以是资产） |
| **成长** | 基因层（内建纪律，不学）／步骤经验（`rules.md` 按步骤）／岗型方案（待建） | 见决策 22；越攒越省人 |
| 会话记忆 | SDK JSONL（`bestagent\.sessions\`）／DSH sessions（`~/.dsh`） | **可丢**，不作为任何依赖（铁律：**不赌会话记忆**，每轮注入状态卡与路径） |

> 老板的用法总结：**"我们自己记录得越多，换电脑也没关系"** —— 这条是整套设计的立足点（决策 9 / 25：底座通用、跑单=攒资产）。

## 7. 纪律与边界（摘要；详版见 `授权矩阵.md` / `设计方案.md`）

- **三权分离**：脚本定流程 / 小猎做判断 / 老板批准（决策 16，非 multi-agent）
- **闸门**：可逆动作全自主；不可逆动作留闸门；**微信 / 电话 / 谈薪资 = 🔴 永远人工**；打招呼 ⏸ 讨论中（决策 18）
- **自由对话 = 只读 + 受控追加**（决策 27）；删/改记录、动代码配置 → 找参谋长或老板
- **采集必须走配方表 `execute_spec`**，禁自然语言驱动浏览器（教训 #2）
- **小 JSON + 本地渲染 HTML**，禁 agent 手写长 HTML（教训 #17）
- **分批**：池子评估 ≤72 人/批、打招呼数据 ≤5 人/批（教训 5/15）
- **判断错不罚，不诚实必罚**（persona 与实施纪律）
- **平台风控**：搜索次数不计、只看查看简历/沟通（教训 18）→ 管好轮间节奏 8-20s
