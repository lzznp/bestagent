### 2.2 两个检查点怎么"收进采集"【已实测（单测）+ 真实计划已验】

原「搜索体检」子步骤的两块能力，**装在执行器真正开跑的那一步**（而不是留一个按钮）：

1. **开工前先报池子**（`collect_exec.search_page`）：给 `execute_spec` 传 **`on_step`**
   （照抄 `search_rounds.run_rounds` 的 `_hook`）→ **每个条件执行完就地读一次「共N位人选」**
   = "这个条件砍掉多少人"；搜索定稿后再读一次 = **这条关键字+这串条件到底多少人**。
   · `input` 类条件不触发搜索 → 读数**如实标 `stale`**（不冒充它的效果）；
   · 读数进轨迹 `searches[i].pool` / `pool_by_step`（**0 token、报告里能看**）；
   · 读不到就写"读不到"，**不许当成"池子薄"**。
2. **开工前体检**（`collect_exec.preflight_plan`，`--plan` 路径在**开搜之前**跑）：
   `local_checks.check_collect_spec`（关键字形态 + 条件组存在 + 取值在配方表合法档）
   \+ `check_judge_card`（同组多值 = "同时满足" → 0 命中 / 连写复合词 / **缺判据卡**）。
   **`problems` → 拒绝开跑**（打印原因 + `SystemExit(2)`，**一个字都不采、一个人都不开**）；`warnings` 只打印。

> **为什么必须放在执行器里**（而不是留在面板）：老板拍板取消那两个子步骤后，小猎是**一个回合内**自己写完
> 计划就直接开跑 → 面板**来不及在中间拦一道** → 最后一道闸门必须在**真正开跑那一步**。

**真实计划实测**【已实测】：拿 094907 那份真计划 `collect_plan_20260916-152048.json`（15:21，机械判据卡）
跑体检 → **✅ 通过**，1 处提醒（行业词「叉车AGV」是连写复合词，与上一场 §2.9 的结论一致）。
→ **这份计划下一次真跑不会被闸门拦住**。

### 2.3 「无计划也能跑」：一回合内自定计划 + 留档 + 直接跑【已定 + 已实测（单测）】

`build_step2_run_task(job, plan_file=None)` 现在有两个分支：

- **有计划**（原口径不变）：读计划 → `collect_exec.py --plan <那份> --all-keywords`；
- **无计划**（新）：任务书第一句就是"**盘上还没有采集计划 → 这一个回合里你自己把计划定下来，然后直接开跑；
  中间不许停下来问老板**"→ 自定 关键字/条件/判据卡（值只能从配方表选）→ **写 `collect_plan_<ts>.json` 留档**
  （可重放）→ **`--all-keywords` 立刻跑**。
  首行仍用「老板已确认【步骤②」前缀 → `kind_of_task` 照旧判 `collect_run`（**不必新增映射**，已验）。

⚠️ 配套改了 `CAPABILITIES`（它会被拼进**每一份**任务书）：把"计划要**请老板确认后才执行**"这句过期口径
