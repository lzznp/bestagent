## 1. 缘起：为什么会有这场审视

- 老板开场感觉整个系统"**差点意思**"，聊开后定位到根源：产品长成了"一个很好用的执行器 + 一个等着被指挥的界面"，不是当初说的"合伙人"。
- 认知层面：最初的"数字合伙人"愿景是在 **LangChain 语境**（网页版曾建议"调度 agent / 简历 agent / 沟通 agent 开会"的模型）+ **对 harness SDK 能力不了解**的迷雾里，与当时的 AI 共同制定的——概念有包装成分，缺"老板真实的一天"作锚。
- 一年实测给出的现实：
  - agent = **可靠的无状态执行单元**（会话记忆不可靠、单次输出有限、会撒谎需纪律注入、判断质量在线）；
  - 脚本编排（三权分离：脚本定流程 / 小猎做判断 / 老板批准）= 可靠、省 token、可审计；
  - "让 agent 自己定下一步 / 互相开会"模型实测不适用（v1.6.1~1.6.3 三轮为证）。
- 与主流用法对照：多数人把 harness 当 **codex/编码助手** 用、或改插件皮肤；老板把 SDK 当**业务执行引擎**用 = 更接近设计意图，但还没资产化——"领先只是自嗨"，要变成可迁移、可复制的东西。

## 2. 老板的真实流程（本次梳理定稿）

```
① 拿 JD → 和 PM 沟通 → 理出"原始资料"（口径/佣金/硬性条件）
② 第一轮搜索（评估/探池）：换关键字+条件组合，看总人数、看换词后是否还是那几个人
   → 池子薄 = 这岗费劲 → 影响做不做（轻量感知，不开详情页、不入库）
③ 决定做 → 岗位先入库（底座，以后匹配都对着它）
④ 第二轮搜索（采集期）：按 JD 精调关键字/条件 → 看到人 → 开详情页大眼扫 →
   感觉差不多 → 插件/热键抓进候选人库（岗位库 ↔ 候选人库 关联）
⑤ 攒到一批（~50 人）→ 匹配（逐人打分）→ 打招呼指导报告
⑥ 照着报告复制话术 → 逐步联系候选人（大量最终转微信）
⑦ 边干边学：跑单中发现规律当场沉淀（如：猎聘 10 页以后候选人明显与 JD 无关）
```

关键特征（与现系统对照的锚点）：

1. **老板自己是筛选器**："采集"= 人眼扫详情页、判断"差不多"才入库；工具只是输入装置。判断大头在人。
2. **两轮搜索分工不同**：第一轮探池（厚薄），第二轮真采集（精调）；关键字不是重点，重点是"池子信号"和"搜索姿态"。
3. **岗位是长期底座**：先入库、跨天跟进、多岗并行、规律跨岗复用。
4. **流程天然是边干边学**：发现（10 页后无关）→ 当场变规则。
5. **日常主战场是沟通**：直接开聊为主、打招呼→回复→转微信。

## 3. 与最初设计的异同（定性）

**定性：愿景的现实校准 + 交互形态换代。非推翻、非倒退、也非普通改善。**

| 保留（实测有效，一句未否定） | 改变（都对应实测中的别扭） |
|---|---|
| 小猎做判断（评分/拆计划/话术） | "自主"的定义：agent 自己跑链路 → **按已积累方案执行、人放手** |
| 脚本定流程（幂等续跑、可单步重跑） | 交互：步骤制面板（发令→等报告）→ **对话驱动判断**（聊出来的判断 + 联合探索） |
| 产物 = 资产（数据/展示分离、HTML 本地渲染） | 成长：纠错→规则（防御性）→ **探索→方案**（建设性，岗型方案层） |
| 不可逆动作留闸门 | 汇报节奏：步骤制每步停 → **方案授权阶梯**（越成熟越放手） |
| 记忆在文档不在会话 | 产品主战场：上游跑岗 → **下游沟通跟进延伸** |

**被推翻的唯一想象**："丢个 JD，它自己全自动跑完整条链"——浪漫想象，实测证伪（判断要对话、探索要协作、采集要人眼、放手要方案）。

## 4. 结论六条（决策 #19-25 的展开）

### 4.1 交互模型：对话驱动判断（决策 20）
判断环节在**对话里**完成——小猎给态度和理由（"钓鱼单，别做" / "可以，咱做"），老板反驳追问；执行环节仍走脚本 / auto_job（可靠性不丢）；产物自动留档到岗位下；按钮退居"执行显示层"；不可逆动作前对话确认闸门保留。**m3_chat.py 是主载体，列为新对话 P0**。

### 4.2 岗位模型：长期底座 + 多岗并行总览（决策 21）
岗位 = 长期对象（JD 底座 + 原始资料 + 状态 + 历史产物 + 跟进），会话临时、岗长久；提供"待我处理"总览（多个岗卡在哪、等你什么）。修订"一岗一会话"。

### 4.3 成长三层挂载（决策 22，老板类比：打屁股来自基因 = 价值观不该靠学）
| 层 | 装什么 | 什么时候被读 | 现状 |
|---|---|---|---|
| 基因层（顶层综合） | 诚实、不粉饰、不越界、工具纪律——**内建不学** | 每次执行前（persona/纪律） | ✅ 已有，需正名为顶层设计 |
| 步骤经验层 | 业务动作的坑：分析怎么评准、采集条件怎么设、口径别写死、"10 页后无关" | 执行到那一步时 | 🟡 rules.md 按步骤分节，内容待攒 |
| 岗型方案层（新增） | 一整类岗的打法 = **方案 A/B**（搜索姿态、采集深度、报告模板） | 遇到同类岗时整包调出 | ❌ 完全没有——"按方案 B 执行"的那个 B |

成长载体从"纠错账"扩为"探索成果 + 经验"；纠错只是输入之一。修订 2026-09-05"完整成长机制暂缓"：不再等纠错攒够再设计，先搭分层载体（机制细节实施对话前定）。

### 4.4 放手阶梯：按方案授权（决策 23，细化决策 16 §6.2）
对话把关（现状）→ 已验证步骤放行（执行自主，--auto 类）→ **成熟方案整体授权**（按方案执行、只报异常与不可逆闸门）。油门 = **方案成熟度**（该岗型跑过次数 / 纠错率 / 老板亲手确认过方案），不是抽象信任分。

### 4.5 产品主战场：沟通跟进（决策 24，衔接决策 18）
系统应向下游长：平台侧"第一公里"（打招呼 + 初轮应答）自动 + 沟通状态/记录自动归集（candidate_events），转微信后上下文不断；微信侧远期。微信/电话、谈薪资承诺**永远人工不变**。详细设计另开一场（非本场范围）。

### 4.6 资产化：跑单 = 攒资产（决策 25，回应"领先只是自嗨"）
每次探索/跑单自然产出可复用件（岗型方案、搜索配方、报告模板、规则），方法论按三层归位——攒的是**换领域也能带走的资产**（决策 9 底座通用 / 决策 13 变现后置的落地口径）。

## 5. 产品一句话画像（v2 校准版）

> 一个**对话协作的猎头合伙人**：判断在对话里来回，它给态度和理由；它**记得你们一起攒的方案与规律**，同类岗越来越懂；攒够了你能**按方案放手**（"按方案 B 执行，JD 在这，我去喝酒了"），它只在该叫你时叫你；它的主战场跟着你走——**沟通跟进**，而不只是上游跑岗。

老板的朴素三句（本文档的"人话版"）：
① 有个懂行的搭档能跟我**聊判断**；
② 它**记得**我们一块儿攒下的东西、越用越懂我；
③ 攒够了它能**按方案自己接活**，我放手去搞沟通。

## 6. 明确不变（防回潮清单）

- 架构：单 agent 流水线、三权分离（设计方案 §6 不推翻）；DSH 用确定性端。
- 边界：可逆动作全自主、不可逆动作留闸门；微信/电话/谈薪资永远人工（授权矩阵 §3 阶段3 不变）；打招呼 ⏸ 讨论中（决策 18 维持）。
- UI = 壳，产物/数据 = 资产；数据/展示分离；记忆在文档不在会话。
- 成长不含模型训练；成长 = 外部文档记忆。
