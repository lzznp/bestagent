## 2. 本场主要结论

### 2.1 token 账的**目的**变了（【已定】老板当场纠正）

> 老板原话大意：**"3000 元红线"是上个对话开玩笑说的**，真实意图是——**如果我们设计不当，消耗了不该消耗的 token**。

① 每次问话的**固定租金**（工具面）；② LLM 手写**展示层**的量；③ LLM 干**代码的活**（数数/排序/查重）的量。

### 2.6 事故与本场最重要的机制修补（【已实测】→【已修】）

**事故**（09-14 17:24，老板新建的"电气设计工程师"岗首跑）：

```
第 2 轮 out=8192 正好撞上输出上限，turn/end reason = {"kind":"max-tokens"}
文本只有 81 字符（"…现在写两份产物"）→ 剩下 8 千 token 全耗在一个被打断的 write 参数上
→ reports/ 空的，两个文件全丢
```

- **根因是我的 regression**：我上午写的"两个文件写完之后不要再回读……把力气全花在判断上"，
  把它推成"**一趟把两个大文件都写掉**"；基线那次是**分两步**写的（JSON 2,662 + 网页 5,013，各不超限）。
- **它暴露的病更严重**：`reports/` 是空的，`state.json` 却写着 `step1_analyzed=true`、`decision=pending`
  → **系统自己假装执行了**（"不许假装执行"这条纪律，这次违反的是系统）。

**修了三处（【已修】+ 09-15 09:16 复跑验证成功）**：
1. 任务文本：写成"**第 5 步只写这一个文件**"+"**第 6 步再单独一次**"，并把事故原因写进指令防重犯；
2. ①分析输出上限 `8,192 → 16,384`（安全网，与 greet 同档）；
3. **面板不许假成功**：跑完**先判本次有没有真产出 analyze JSON**；没有 → 不置完成、清掉误置决策、
   对话里贴一条 `⚠️ ①分析没有产出文件——本次运行结束原因：<finish_reason>`。
   （实现：模块级 `LAST_RUN` 字典带 `finish_reason` 出来，**不动 `run_assistant` 的 3 元组签名**，避免打断既有调用点/自测。）

> **为什么这条比省 token 重要**：**"被截断"从最终回复里看不出来**（它说"现在写两份产物"，听起来很正常），
> 只有 `finish_reason` 和产物清单能识破。这一步把"不许假装执行"从**小猎的纪律**变成**系统的机制**
> —— 正是 §2.7「闸门挪进门里」的方向。

### 6.5 环境备忘（**新增项**）

- **`_apply_patch.py` 为什么存在**：本机对 `m3_chat.py` 这类"被 Streamlit 看着"的文件，
  `edit`/`write` 工具的原子替换会报 **`ReplaceFileW EIO (Win32 1175)`**（不是文件锁——`[System.IO.File]::WriteAllText` 原地写是好的）。
  故改用"补丁文件 + 原地替换"：`python _apply_patch.py <目标> <补丁>`，**每段 old 必须恰好唯一匹配，否则整体不写**。
  ⚠️ 顺带确认：`write` 工具对**已存在**的文件也会撞 1175，但**新建**文件正常。
- **沙箱崩过一次**：`windows-acl-run: --temp is not an existing directory: C:\Users\84005\AppData\Local\Temp\dsh-agbpcL`
  → **所有 pwsh 命令被拒**（"refusing to run unconfined"）；**重启 `dsh web` 后恢复**。文件工具（read/grep/glob/write）不受影响。
