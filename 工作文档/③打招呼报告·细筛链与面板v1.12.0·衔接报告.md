### 2.1 老板定的新形态与**北极星**【已定】

代码侧**天然支持**：打过招呼的人进"等回复"，第二天重出报告时主名单**自动就是剩下的人**。

**北极星**【已定，老板原话】："要是一个不知情的人用小猎做他的助手……他用了很久，他甚至不知道这个小猎是 AI，

### 2.3 打招呼报告（**小猎的工作依据**）【已实测】

`greeting_report.py`（本地渲染，**0 token**）+ `report_html.render_greeting()`：
- **分区**：🟢今天该打（够分 + 没打过，按分降序，受名额上限截断并如实报"另有 N 人没列"）｜🟡等回复（含"打了几天"）｜
  🔵有回复（该聊下一步）｜⚪已排除（**只给计数、不列名单**）+ 一行**日报**（今日新增/该打/等回复/有回复/已排除）；
- **时间窗**：`window_ok()` 给"现在能不能打 + 为什么"（默认工作日 9:30-12:00、14:00-18:30；周末不发）；
- 🔴 **前置检查（老板要的"发脾气"）** `greeting_ready()`：**报告在不在 / 比最后一次采集或细筛新不新 / 现在能不能打**
  → 全是**代码判定**，不过就**拒绝执行**（"我不会自己临场挑人、也不会自己编话术"）。
  ⚠️ 关键点：**"能不能打"的最终判决来自脚本，不是小猎的心情**——不然它哪天"自信"就会拿旧名单打。

**真实产物**：`打招呼报告_20260917-105842.json`（44KB）+ `_过程.html`（43KB）；
主名单 15 人（82 分 1 人 + 78 分 14 人），另 24 人够线但超名额没列（分在库里，调 `max_list` 0 花费重出）。

### 2.6 修掉的真 bug：`new_tab` 取错一层 → 假全文 + 标签页堆一排【已实测】

| 环节 | 事实 |
|---|---|
| 扩展 `new_tab` 返回 | `{ok:true, tab:{tab_id:N, active:true}}` |
| 桥（`server.py:129`） | **原样**存进 `result` |
| 老代码（`collect_exec.open_detail`） | 读 `result["tab_id"]` → **永远 0** |
| 扩展收到 0（`background.js:1132`） | 0 是假值 → 当成"**没指定**" → **读当前激活标签页**（只有"指定了但页没了"才报 tab-lost） |
| `finally` 里 `if new_id:` | 也是 0 → **详情页从来没被关过** ← 老板说的"浏览器里堆了一排标签页" |

后果（都已实测）：① 3 份"全文"其实是 **DSH 面板页的文本**（那次老板正在看面板；三份 11581/11596/11596 字几乎逐字相同）；
② 60/63 之所以对，是因为扩展 `active:true` 开页、**多数时候激活页正好就是它**。
**修法**（`RESUME_MARK="简历编号"`）：`_tab_id_of()` 取 `result.tab.tab_id`；**取不到就放弃这份全文、不猜**；
**读完必关**（+切回列表）；**读到的必须像简历**（不含「简历编号」→ 判失败、同一标签页再读一次，**绝不写库**）；
详情页 URL 还要和这个人的 `res_id` 对得上。**测试 +13 条**（钉住/必关/无 tab_id 不发读页/URL 不匹配/不像简历）。
⚠️ 老采集器 `detail_collect.py:146` 有**同一行错**（抄的），现在没被面板用到，**没改**。
