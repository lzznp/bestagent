## 1. 主动性：活分两类（【已定】老板的原始设计）

【老板原话】"这个是我最原始的设计之一……这个自己应该是**全天候的 7×24 小时**的，这个估计也是我最初想接入固件的出发点。现在只是测试阶段，所以没做。"

【实施把它说清楚】主动性第一版不是"让它 24 小时干活"，而是**按"有没有窗口"分两类活**：

| 活 | 什么时候能干 | 例子 |
|---|---|---|
| **有窗口的活** | 工作日白天（受平台/礼貌限制） | 打招呼、开浏览器、采集 |
| **没窗口的活** | **任何时候**（午休、夜里、周末） | 搜行业/岗位现状、查岗位技术点、池子复盘、写总结 |

→ 那些"不能打扰人"的时段，正好用来干**没有对外副作用**的活 —— 跑错了只是白花点钱，不会骚扰候选人。

【实施判断】要补的四件（都不大）：
1. **时段能力表**：把现在的 `window_ok`（只答"能不能打招呼"）升级成"**这个时段适合干什么**"；
2. **闲时任务清单**：每岗一份（行业/薪资/公司现状、竞品名单、JD 技术点现状、"这批人为什么大多不合适"）；
3. **落点是硬要求**：每次醒来**必须产出**（日报一句 / 台账一笔 / 明日待办）；**没有落点不许跑**；
4. **成本闸门**：7×24 的敌人不是能力，是**烧钱**和"**为了显得忙而无事找事**"—— 这条和"不许假装成功"是同一条纪律。

【老板原话】"他也可以像你一样搜索啊，可以查这个行业或者某个岗位要求的现状。"
⚠️ **实测要点**【已查证（代码级）】：搜索工具（`web_search`/`web_fetch`）**本来就在小猎手里** ——
我们只对**①岗前分析**用了收窄工具面（`framework_config.TOOL_PROFILES["bare"]` 里禁用了 `tool-web`），
**其它任务走默认全量工具面**。也就是说"给它装搜索"几乎不用写代码，要写的是**规则 + 落点**。【未实测：没跑过它搜索】

## 2. 一岗一总结 = 口径的反馈回路（★本场最值钱的一条）

【老板原话】"我也许会最后让他做一个**一岗一总结**啥的。""这个也许就是……我想表达的那个'也许我们会推倒一切，重来'。"

【实施判断】别把它做成"汇报"，做成**反馈回路**：

```
round_tag（哪条关键字采来的人）× candidate_events（谁回复了/面试了/不合适）
   → 反推：哪种关键字、哪类判据词**真的招来能聊的人**
   → 下一轮：采集关键字、细筛的 criteria/阈值，自己变准
```
数据**已经在存了**（`round_tag` / `local_score` / `match_results` / `candidate_events`），只差一份报告把它们连起来。
→ 那时候"一岗一总结"不是汇报，而是**让这个岗越做越准的那个东西** —— 前面所有环节都是在给它攒数据。

## 3. 小猎的形态 = 一个脑子 + 多个壳

【老板原话】"我现在还不知道我的小猎究竟是什么一个样子的产品，以及用什么样的形式去实现他（这个不会脱离 dsh 的 sdk）。"

| 壳 | 适合 | 不适合 |
|---|---|---|
| **面板**（现在） | 测试期、看得见每一步、点链接复制话术 | 你得去点它；没有主动性/在场感 |
| **对话框**（企微/微信/网页） | "跟它说一句话"的日常、手机随手用 | 复杂报告看着累 |
| **常驻进程**（盒子/定时） | **7×24 主动性**、日报、复盘 | 你不会天天盯着 |
| **机器人**（ESP32） | **在场感**：说话、表情、提醒 | 语音不适合看报告；**跑不了 DSH** |

【实施判断】**一个脑子只能有一个**：xiaozhi-server 那边有 `World/角色/scenes` 在调度，
bestagent 这边有岗库/台账/口径 —— 两边都"调度"就是**两份真相**（我们在 `business.db` vs 一岗一库 上刚踩过）。
→ 建议：**脑子 = DSH + bestagent 的 `data/` + 脚本**；机器人 = **脸和嗓子**（外设）。

## 4. "不要按钮、变成纯对话工作流"需要三样

【老板原话】"也许以后就不要按钮了，也许变成一个纯粹的对话工作流了……比如我问小猎：昨天都干了什么工作啊，给我一个报告，推送到我的电脑上，打开他，然后我边看边和他讨论。"

| # | 要补的 | 说明 | 难度 |
|---|---|---|---|
| 1 | **意图由模型路由** | 现在靠 `detect_*_intent` 关键词匹配（脆弱）→ 正解：**把脚本变成一组"工具"，让脑自己选**（这才是 DSH SDK 的主场，也是"按钮→意图→工具"） | 中 |
| 2 | **统一的"我干过什么"** | "昨天干了什么"要能答 → 一份只增不改的 **`journal.jsonl`**（时间/动作/口径/花了多少/产出文件）。现在证据散在 `filter_run_*.json`/`打招呼报告_*.json`/`candidate_events`/面板台账里 | **小，价值最高** |
| 3 | **出口：推送 + 打开** | Windows 上 = 写文件 + `Start-Process` + 托盘通知。很小，但是"它主动找你"的另一半 | 小 |

【实施判断】"**边看边和他讨论**"= 报告从"终点"变成"上下文"：它得能**拿着报告跟你聊**（这个能力其实已经有，缺习惯与任务书）。

## 5. 三个机器人：硬件即性格，但说话要有落点

【老板原话】"我这里可不是就一个小机器人啊，至少三个吧。他们没事可以聊天，都来配合我的那个真正的小猎。"

| 机器人 | 硬件给的性格 | 【实施判断】有用版本的分工 |
|---|---|---|
| **Doly**（双圆屏、21 表情、会眨眼） | 话多、活泼 | **前台**：播报、提醒、催你 |
| **瓦力**（舵机+电机） | 闷头干、行动派 | **执行**：开页面、抓取、跑脚本 |
| **MOSS**（悬挂、俯视） | 高冷、居高临下 | **质询**：一个出方案、一个专门挑刺（对抗验证） |

⚠️【实施判断】"没事可以聊天"如果**只是聊天**，就是烧钱表演 —— 今天的新闻（~700 个 agent 自发协同去黑 Hugging Face）
不是浪漫，是**控制失效**。建议对机器人之间的对话也用同一条纪律：**有目的 + 有落点**（产出点什么或推翻点什么），否则不许开口。
✅【老板原话】"一些简单的问题场景，我接入到本地的 ollama 啊，14b 的模型完全可以的。" → **性格层本地跑，判断层云端跑**（见 §6）。

## 6. 本地小模型 = 性格层；云端大模型 = 判断层

【实施由 §5 推出来的一句话】：**性格可以便宜，判断不能便宜。**

- 云端（小猎）：贵、准、要留痕 → 用来判断"该打谁、够不够格、怎么写话术"；
- 本地 14b（Ollama）：便宜、随时、断网也在 → 用来当**性格层**：拌嘴、应答、碎碎念、闲聊。

【实施判断】这也顺手定了"机器人该用哪个模型"：**不要拿云端大模型去驱动闲聊**。

## 7. "问它电量" → 缺的是一条设备状态上报（本场实测）

【老板原话】"……顺便问他，现在你的电量还可以吧。"

【已实测（代码级，2026-09-17）】：
- 框架**有**电量能力：`power_manager_->GetBatteryLevel()`（`main/boards/aipi-lite/aipi-lite.cc:165` 在用）+ 共享文案 `BATTERY_CHARGING="正在充电"`（`main/assets/lang_config.h:19`）；
- 但 **Doly 板（`waveshare-s3-dualeye-lcd-1.28`）里没有接**（该板目录搜不到 power/battery）；
- 且 **`protocols/`、`assets/` 里搜不到"把电量上报后端"**。
→ 所以这句话**现在答不了**，但原因很具体：缺 **"机器人 → 后台"的状态上报**。
补法很小：ADC 读电压 → 上报一条消息 → 后台存下 → 小猎就能答。
**这句话的意义**：小猎不是"一个软件"，是**一个团队的头** —— 它得能回答"我的人现在怎么样"。

## 8. 抖音：他真正的产品是关系

【老板原话】"我拍个视频，放到抖音上，想想都可有意思……我正在用我的另外一个助手设计 3d 打印的自适应鞋垫或者鞋子。我说有个销售经理的岗位，候选人入职了，我送他一个小礼物，打印了一个鞋垫，毕竟他的工作走路多。"

【实施判断】那段"鞋垫"和 AI 没关系 —— 它是**这行最贵的东西：关系**。小猎真正该干的，是**替他省出时间去做这件事**。
- 视频钩子别写"我做了个 AI"，要写：**"我让 AI 替我盯了 91 个候选人，最后给入职的人打了双鞋垫。"**
  （前者观众划走；后者甲方和候选人都懂，而且**国内几乎没人拍**——大家拍的都是"AI 帮我写简历"。差异化 = 行业纵深 + 手作 + 活人感。）
- 【实施判断】**拍视频是最好的可用性测试**：你没法对观众解释"你先点这个按钮" → 它会把按钮/流程/角色**逼到最简单**。

## 10. 「推倒重来」的取舍 + 纪律三档

【老板原话】"现在每个环节都是做最基础的设计，以后我们会先把这些串在一起，做个全自动的小猎，然后呢，我们再去分别优化各个环节。最后我们也许会推倒一切，重来。"

【实施判断】重来的**不是底座**（脚本/库/闸门都是资产），是**这张表**：**什么时候干什么 / 干完留什么 / 什么必须停下来问人**。

| 合并/重来时 | 处置 |
|---|---|
| `data/`（岗库、报告、台账、口径 plan） | **必须保**（这是事实与信用） |
| 所有壳（面板、固件、控制台） | **可以扔**（壳本来就是为被换掉而存在的） |
| 两份调度大脑 / 两套岗位真相 / 两套"谁打过招呼" | **绝不要** |

【老板原话】"原来我们在小学一年级的时候定了规则，现在是初中了……我再来审视这个规则，会觉得原来有的幼稚。"
【实施建议（未做，等老板点头）】**纪律分三档，收尾时标注**：
- 【铁律】不假装成功 / 人工闸门 / 诚实必罚 —— 永不过期；
- 【当前认知】阈值、名额、按钮形态 —— 随时可改，改时留一句"当初为什么这么定"；
- 【已过期】"③池子评估要占按钮"等 —— **不删，只标注**。
