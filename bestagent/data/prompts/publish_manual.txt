# 发岗手册（小猎 · 猎聘职位发布方法论）

> 用途：把禾蛙/原始 JD 转成**适合逐条复制粘贴到猎聘发岗表单**的字段内容。
> 执行【生成发岗文字】前必读本手册并严格遵守。
> 本手册 = 字段契约 + 合规规则（来自 recruitment-wails 已实战验证的 publish_job 方法论）+ 公司特别提醒（可逐步追加）。
> 数据/展示分离：你只输出下面规定的 **JSON 字段**（小输出），整篇文案/HTML 由本地代码渲染（0 token、永不截断）——禁止手写整篇长文/HTML。

## 一、输出 JSON 契约（严格按此结构，不增不减字段）

```
{
  "company_name": "实际招聘方企业名称（不是外包/代招公司）",
  "job_title_original": "原始职位名称",
  "job_title_normalized": "规范化后的职位名称（搜索友好）",
  "city": "工作城市",
  "salary_original": "薪资范围原文",
  "salary_benefits": "薪资福利（五险一金/补贴等；无则空串）",
  "work_years": "工作年限",
  "education": "学历要求",
  "headcount": "招聘人数（数字或字符串都行）",
  "responsibilities": ["职责1", "职责2", ...],
  "requirements": ["硬性要求1", ...],
  "priority_notes": ["优先条件1", ...],   // 无则空数组 []
  "compliance_issues": ["已删/改写的合规问题，如 '删除年龄歧视词 35岁以下'", ...]  // 无则 []
}
```

## 二、字段提取规则（对照猎聘发岗表单的格子）

1. **company_name = 实际招聘方**：不是外包/代招公司！
   - 若出现「*代招公司：XXX / 签约方：XXX / 科锐国际等中介」→ 那是外包/渠道，**不要提取**。
   - 优先取岗位信息开头/正文的用人企业；禾蛙列表名与正文矛盾时按正文实际招聘方。
   - 没有明确实际招聘方 → 填「未提供」。
2. **job_title_original**：原始职位名称（如挂网名）。
3. **job_title_normalized**：规范化职位名（搜索友好、贴合 JD 正文真实职责）；特例：「爬虫」→「自动化采集」。
4. **city**：工作城市；**多城市/多基地岗用「/」并列全写**（如 上海/深圳/南京），不要只留第一个——招聘量大+多城是卖点。
5. **salary_original**：薪资原文（如 100-200万/年薪10-30万），原样保留。
6. **salary_benefits**：薪资福利（五险一金、补充公积金、餐补、交通补贴、13薪等；JD 无则空串，不要编）。
7. **work_years**：工作年限（原文口径；有矛盾见 §四）。
8. **education**：学历要求（保留原样；有矛盾见 §四）。
9. **headcount**：招聘人数（数字）。
10. **responsibilities**：岗位职责整理成列表：每条一条职责；**删除具体网站名/产品名/内部系统名**（如「电网」→「相关公开网站」）；保留技能与工具名（岗位必需）。
11. **requirements**：任职要求列表：学历/专业/经验/技能逐条；合并重复；**删除歧视词、广告法违禁词、内部信息**；「优先条件」不混入这里（单列 priority_notes）。
12. **priority_notes**：加分项/优先考虑（JD 的「优先条件/加分项」段）；无则空数组。
13. **compliance_issues**：把本次删除/改写的不合规内容逐条记下（给老板看，说明为何过滤）；无则空数组。

## 三、合规清洗规则（逐条执行，删了什么记进 compliance_issues）

### 1. 歧视词（删）
- 年龄：35岁以下 / 35以内 / 年轻有活力 / 不超过XX岁（注意：年龄限制是违法敏感筛选项——**删掉**，如岗位本就限应届可改写为「欢迎应届生/毕业时间窗口」合法口径）
- 性别：男士优先 / 女士优先 / 男性优先 / 女性优先 / 男女均可
- 地域：本地人优先（但「工作地点在XX」是事实信息，保留）

### 2. 广告法违禁词（删/改写）
第一 / 最好 / 唯一 / 顶级 / 国家级 / 百分百 / 绝对 / 全网最低 / 史无前例 / 遥遥领先 / 完胜 / 吊打 / 最专业 / 最优秀 / 业界领先（无证据的「领先」慎用）等。

### 3. 内部信息（删）
微信 / 进群 / 看手册 / 项目手册 / 必问问题 / 寻访须知 / 内部链接 / 招聘渠道内部代号——发岗页面不该出现。

### 4. 具体网站/产品名（删或改写）
- 竞品/内部系统具体名 → 删或泛化（如「电网」→「相关公开网站」）；岗位必需的核心技能/工具名保留。

### 5. 自动改写
- 「应届生优先」→「欢迎应届生投递」
- 「爬虫」→「自动化采集」

## 四、口径矛盾处理（JD 内部打架时）

- **年限/学历/城市矛盾**（如列表 0-3 年 vs 寻访须知 1-3 年、大专 vs 本科）：按**更宽松口径**写入 + 冲突点在汇报里提醒老板「发布前先向发单方核实」；**别写死自相矛盾**。
- 佣金 / 结算 / 内部渠道分成：**永不进发布文案**。
- 外包 / 代招 / 签约主体信息：可写「某知名企业项目」级别，不写渠道公司名（除非老板明确要求）。
- 红线提示：识别到年龄/性别等敏感限制时，除删除外，在汇报里提醒老板该口径不合法、已用合法口径替代。

## 五、公司特别提醒（逐步追加区 —— 优先级最高，高于上述默认规则）

（暂无。新增格式：`- [日期/岗位/来源] 当〔情境〕时，应〔怎么做〕`，由老板或实施对话追加，小猎不自行修改本区。）
