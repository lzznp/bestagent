## 1. 一句话定位

**本工作区只做一件事：把 browser-agent 打磨成"通用、可靠、适用其他网站"的浏览器自动化底座**——一个接口（自然语言子任务 → 结构化结果），换任何网站都能干活。

## 2. 范围（重要：做什么 / 不做什么）

| 做（本工作区） | 不做（其他工作区/系统） |
|---|---|
| 浏览器操作底座：快照/点击/输入/滚动/导航/提取/翻页/多标签/条件采集 | 多 Agent 编排（规划器/调度器）——用户另有工作区，有现成业务代码 |
| 底座可靠性：错误可归因、可恢复、不静默跑错 | 业务层：岗位分析/匹配/话术/推荐报告——用户现有 Wails/Streamlit 系统已实现 |
| 站点知识库机制（轻量站点事实 + 改版检测） | 入库/持久化——**剥离**：底座只返回结构化结果，存储归上层（降级为可选开关） |
| 控制台测试能力（自然语言试跑 / mock LLM） | 视觉模型、消息队列、Playwright/CDP 重架构 |

**用户原话锚点**："我只希望在此工作区解决浏览器自动化的问题，我希望他是通用的，可靠的，适用其他网站的"。

## 3. 拍板决策（本对话讨论结论，全部确认）

| # | 决策 | 结论 |
|---|---|---|
| D1 | 底座形态 | **一个通用底座 agent**，不拆"搜索/采集/打招呼/回复"等业务 agent——底层动作集相同，区别只在任务描述 |
| D2 | 含糊 vs 具体指令 | **本质一回事**：都是"规划+执行"，区别在规划器决策深度；按"最含糊指令"设计规划器能力上限（规划器在新工作区） |
| D3 | LLM 与 agent 关系 | 底座 = LLM（浏览器级决策）+ 工具（执行）+ 记忆（快照/历史）+ 汇报。**操作自主、业务纯执行**——业务逻辑不在底座 |
| D4 | 条件分支归属 | 底座能执行"带条件的完整任务"（内嵌 LLM）；**粒度由规划器决定**：简单分支下放，关键分支（不可逆动作）上收 |
| D5 | 入库 | **剥离出核心契约**：`task_desc → 结构化结果`；SQLite（tasks/candidates）保留代码、降为可选开关 |
| D6 | 知识库定位 | **关联网站的"轻量站点事实"**（语义+锚点+验证），不是"页面布局库"；快照=眼睛（现实）、知识库=经验（预期/语义）；按需沉淀 |
| D7 | 知识库 ≠ 能力注册表 | 站点知识库（knowledge.py，绑域名，给底座 LLM）与能力注册表（SKILLS → /api/agent/skills，通用，给规划器看）**是两个东西** |
| D8 | 知识库维护 | **必须配置化**（JSON/API 可维护）——现在 knowledge.py 是代码=加站点要改代码，违反"不改代码"原则（见 D10） |
| D9 | 预测试 | **不需要 staging/harness**；用"只读试跑 + 人工闸门 + 失败可归因"替代（生产即测试） |
| D10 | 错误分层处理 | 决策错→改任务描述/加知识（不改代码）；站点错→verify 降级+按需沉淀；代码 bug→才改代码（Python/JS 无编译，重启/重载秒级） |
| D11 | 不可逆动作 | **默认人工确认闸门**（发送/发布/删除等），动作分级：只读/低风险/不可逆 |
| D12 | iframe/Shadow DOM | 现有快照不可达，列为已知边界；是否支持待评估（见缺口 G6） |

## 4. 架构四件套（各司其职）

```
工具面（SKILLS）           通用，底座能力清单+Schema → 给规划器/调度者（查技能→派活）
行为规则（SYSTEM_PROMPT）  通用，LLM 怎么用工具/翻页/验证 → 给底座 LLM
站点知识库（knowledge.py） 关联网站，语义+锚点+验证基线 → 给底座 LLM（命中才注入，改版降级）
快照（每步）              实时页面理解 → 给底座 LLM（"快照即知识"核心机制）
```

## 5. 四契约（底座对外接口规范——本工作区核心交付物）

1. **任务描述契约**：规划器怎么写子任务描述（目标 + 边界 + 不可做清单），底座能准确执行
2. **动作分级契约**：只读 / 低风险 / 不可逆 三级；不可逆动作走人工闸门
3. **结果契约**：结构化返回（data + summary + 事件流），入库可选
4. **错误契约**：失败可归因（错误类型 + 原因）、可重试、可换路——**不静默跑错**

## 6. 运维哲学：生产即测试

- **人在回路**：暂停/继续/紧急停止（P2-2 已实装）
- **只读试跑**：新站/新任务先用 snapshot/scroll/extract 跑一遍，看 LLM 决策日志再放正式任务
- **失败可归因**：事件流每步有 think 事件（记录 LLM 理由）——错了能知道为什么
- **不可逆闸门**：点错也错不到不可挽回
- **无编译负担**：全 Python/JS 解释型，改代码=重启桥/重载扩展，秒级

## 7. 已证实缺口（猎聘条件页实测 + 讨论发现）

### G1（实测）：搜索条件选项"看得见字、点不了" ⚠️ 最高优先
猎聘找简历条件页实测：`目前城市：不限 北京上海深圳... 其他`、`工作年限`、`教育经历` 等选项在 body_preview 里可见，但**元素列表 56 个编号中没有任何一个对应它们**——选项是带点击事件的 span/div，现有 isInteractive 检测（a/button/input/textarea/select + role + tabindex + onclick）抓不到。
**结论**：底座无法设置复杂搜索条件。解法：
- 加 **click_by_text 工具**（按文本点击包含该文本的最小可点元素）——通用，任何站适用
- 快照可点元素检测增强（cursor:pointer / class 含 option|select 的 span/li）
- 验收场景 = 猎聘条件页复杂表单试跑（见任务书 T2）

### G2（用户报告）：弹层交互链（其他→内镶小页面→确定→整页刷新）
- 若弹层是 iframe → 当前快照不可达（合并 G6）
- 确定后**整页刷新** → 已设条件可能被重置 → agent 需重快照并确认条件保留
- 需在实现 click_by_text 后用本页实测确认弹层形态

### G3（实测）：LLM 无进展打转
E2E 曾出现连续 13 步只发 snapshot（原地打转）耗尽 max_steps。需要**无进展检测**：连续 N 步无实质变化（无新数据/无页面变化/重复动作）→ 终止并报"卡死"。

### G4（实测）：tab_id 失效静默回退
钉住的标签被关闭后，扩展静默回退到激活页（可能跑错页）。应明确报错。

### G5（实测）：合成事件边界
chrome.scripting 只能派发合成事件（input/change），个别组件不吃（诚猎通某输入框 type 不生效）。保持注入架构，遇到报"该输入框不受支持"——不引入 CDP。

### G6（已知）：iframe / Shadow DOM 不可达
快照基于 document.body 遍历。通用化需评估：渗透 iframe 遍历 vs 声明不支持。
