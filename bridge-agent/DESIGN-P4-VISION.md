## 2. 讨论结论（全部达成一致）

| # | 结论 | 说明 |
|---|---|---|
| V1 | **坐标问题不用 LLM 解决** | 通用 VLM 直接吐坐标不准（P2 实测：能发现按钮、无法确定位置）。业界两条替代：**SOM**（截图给元素画编号 ①②③，模型选号，坐标由标注层负责）和**解析器**（OmniParser：截图→结构化元素清单，LLM 在清单上决策）。我们走 SOM：编号逻辑复用现有扩展 `isInteractive` 遍历 |
| V2 | **视觉≠每步截图** | 截图是"侦察兵"不是"必需品"。简单页（提取/翻页）DOM 已很好，零截图；只有复杂交互（城市弹层多选）、首次见、或经验失效时才截图 |
| V3 | **截图是可复用资产** | 运行时截图（触发式拍）+ 沉淀截图（首次成功处理复杂交互时存进经验条目，作为记忆的一部分，用于"当前 vs 记忆"对比） |
| V4 | **自学习闭环 = 现有机制的补全** | 现有：知识库配置化（T6）+ verify_site 基线检测（site_changed 事件）+ 降级纯 LLM。缺的只是**自动沉淀**：成功路径自动写回知识库（version+1），把"人工改 JSON"变成"agent 自己学" |
| V5 | **新模型可用** | DeepSeek-V4-Flash-Vision-Exp 已上线（多模态，Chat Completions/Messages/Responses），Agent 能力评测接近 Opus-4.8。它是**通用视觉理解**模型（看懂布局/语义），不是专门 grounding 模型——配合 SOM 方案用（看图选编号） |
| V6 | **业务特性支持边干边学** | 猎头找简历非实时交易：允许慢（几分钟）、允许失败重试、允许事后沉淀。学习代价可接受，收益长期 |
| V7 | **脏经验要防** | 自动沉淀走置信度门槛或人工闸门：低置信（探索有误点/重试）只提示不写回；高置信（一次成功无异常）才自动沉淀。版本机制保留历史供回退 |

## 3. 三层架构（插件=手，视觉=眼，经验=脑）

```
经验库（脑）      knowledge_config.json 扩展为 experience 条目：
                  {站点, 关键路径, 锚点, 元素特征, 关键截图, version, 置信度}
    │ 命中（按记忆走，少决策少截图）
    ▼
agent 循环        快照（DOM 编号+文本） + 按需截图（SOM 标注编号）
    │ 记忆失效（锚点找不到 → site_changed）
    ▼
重新探索          截图 + 视觉模型理解新布局 → 操作 → 成功
    │ 自动沉淀（高置信才写回，version+1）
    ▼
经验库 +1 / 更新
```

**改版检测 = 记忆 vs 现实**：真人发现改版是因为"看到的和记忆里不一样"——系统同理，verify_site 基线 + 经验锚点对照，不一致 → site_changed → 重新探索 → 写回。这就是自学习。

## 4. P4 任务书（按依赖排序，建议顺序）

| # | 任务 | 要点 | 验收 |
|---|---|---|---|
| V-T1 | **screenshot 能力** | 扩展新增注入型动作 `screenshot`（chrome.tabs.captureVisibleTab → dataURL → bridge 落盘 `logs/screenshots/`，返回文件路径）；归入只读动作（与 snapshot 同级，无需闸门）；CLI/bridge 可调 | 单步：对猎聘页截图成功，PNG 可读 |
| V-T2 | **视觉问答验证**（主线，纯测试不写业务代码） | 测试闭环：agent 截图 → 提问 DeepSeek-V4-Flash-Vision-Exp → 结合快照交叉判断 → **用户做真值验证**（确认动作准确性/内容正确性）。顺序：① 简单页储备（候选人列表/条件页干净态，验证基线理解力）② T2 复杂页逐步（条件页→点"其他"弹层→选城市→混合态）③ 结论：视觉能否支撑"看图选编号"的 SOM 方案，还是只够"确认布局/检测改版" | 每轮产出：截图 + LLM 解读 + 快照对照 + 用户确认，形成数据表 |
| V-T3 | **经验沉淀（自动写回）** | 成功任务结束后：从事件流提取关键锚点/路径，写入 experience 条目（自动起草）；高置信才自动生效，否则提示人工确认 | 跑两次同任务：第二次按记忆走（少决策）；改版模拟 → site_changed → 重新探索 → version+1 写回 |
| V-T4 | **记忆 vs 现实对比** | site_changed 触发时，把"当前截图 vs 经验沉淀截图"纳入检测（视觉确认是否同类布局），减少误报/漏报 | 模拟改版：截图对比能辅助判断 |
| V-T5 | **截图资产沉淀** | 首次成功处理复杂交互（如城市弹层）时自动存关键截图入经验条目；后续"疑似同类弹层"用截图对比确认 | 经验条目含截图；二次命中时引用 |

**V-T2 用户参与方式**：测试由用户配合操作浏览器（点击/输入/切换页面），用户向 agent 汇报"动作是否点对、内容是否抓对"；agent 侧判断"这种模式下现有代码能否高效完成工作"。

## 5. 参考（业界方案，讨论中查证）

- 坐标问题替代方案：SOM（Set-of-Mark）编号标注 / OmniParser（微软，截图→元素清单，二代延迟降 60%）
- UI-TARS（字节开源）：原生 GUI agent 模型（训练过 grounding），纯视觉 agent 代表——但文本提取/精确数据抓取弱于 DOM，故生产系统普遍混合
- DeepSeek-V4-Flash-Vision-Exp：多模态 Agent 能力接近 Opus-4.8（评测），支持三种 API 格式；通用视觉理解，需配合 SOM 用

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 脏经验（学到错误路径如误点） | 置信度门槛 + 人工闸门（V7）；误点场景（如点中"成都三快在线科技"）计入低置信 |
| 经验震荡（A/B 路径反复切换） | version + 历史保留，回退可人工比对 |
| 截图成本（base64 传输 + 多模态推理） | 只触发式截图（V2），不每步拍；截图压缩/缩略 |
| 视觉替代不了结构化提取 | extract 走 DOM（文本精确性 DOM 永远赢），视觉只做布局理解/异常发现 |
